# M2 persistent GPU execution: final evidence

Completed 2026-10-01 on branch `cpp-foundation`. Scope and resolved defaults:
[M2 plan](M2-plan.md). Mathematics and lifecycle: [CONTRACT.md](../CONTRACT.md).

## Delivered behavior

- Move-only `kan::cuda::ResidentNetwork` executes arbitrary compatible mixed-family
  networks using all six M1 bases, double precision, analytic input derivatives,
  fixed-order contractions, finite-result checks and network-wide atomic GPU SGD.
- Each instance owns its stream and two device allocations containing inputs,
  upstream, parameters, activations, basis values/derivatives, gradients and SGD
  candidates. Repeated numerical calls and batch changes within capacity allocate
  no device memory. Uploads/downloads are explicit; numerical calls check scalar
  status. Successful SGD commits by swapping validated arena regions.
- Optional strict float64 NumPy bindings expose basis evaluation, CPU layers and
  networks, gradients, resident execution and training. Arrays/snapshots own their
  results. CPU C++ builds retain no Python/CUDA dependency. Python builds and
  prefix installations work without adding M6 wheel distribution or serialization.
- Frozen full-call benchmarks compare CPU, M1 host CUDA, M2 resident and M2
  transfer-inclusive execution. Nsight Systems identified and verified elimination
  of repeated allocation/stream creation, repeated basis recurrence and SGD copies.

## Independent review and performance conclusions

The CUDA author reviewed Python lifetimes, strict-array validation, shape metadata,
snapshot ownership and GIL handling. The Python author independently reviewed CUDA
mathematics, layout/bounds, ownership/cleanup, state flags, reductions and atomic
SGD against the CPU implementation. Constructor GIL release and basis-configuration
snapshot suggestions were incorporated. Neither review found a blocking defect.
The coordinating agent independently reviewed both sources and benchmark semantics,
authored the additional four GPU cases, and reran the final gates above. Details:
[review evidence](M2-review.md), [CUDA evidence](M2-cuda.md), [Python evidence](M2-python.md).

Before the roadmap closure, the benchmark agent independently audited this final
evidence against the acceptance plan, lane records, live validation logs, hosted
CI and committed artifacts. It confirmed gate counts, commit provenance, links,
six-family/76-row measurements and all 16 evidence hashes, with no blocking
contradictions. It also confirmed the performance claims retain their measured
scope and profiler/WDDM limitations.

Full matched measurements and profiler evidence are in [M2-benchmark.md](M2-benchmark.md).
For the frozen Chebyshev 64 -> 64 -> 32 -> 16, batch 1024 case, observed complete
training-step medians are CPU **224.582 ms**, M1 host CUDA **35.613 ms**, M2 resident
**2.109 ms**, M2 including uploads/output and gradient downloads **4.008 ms**.
Setup is separately reported. These compare this library's public workloads, including
M2 activation reuse, against its serial CPU reference; they are not general hardware
or other-library speedup claims.

Balanced matched runs support the SGD arena swap's modest small resident-call benefit
(6.34% and 3.35% in two frozen cases). Broader/transfer-inclusive tuning gains remain
uncertain. WDDM/display activity and unlocked clocks limit measurements. Nsight Compute
counter access was denied; Nsight Systems proves the targeted execution removals but
does not establish full occupancy or saturated bandwidth. Those limitations are
preserved explicitly in the benchmark evidence.

All M2 tasks and declared acceptance gates are satisfied. M3 is next; splines,
wavelets, trainable RBF configuration and adaptive grids have not been implemented
as part of this stage.
