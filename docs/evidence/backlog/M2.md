# M2: pole-free rational denominators as a singularity policy

Backlog item M2 (P0), stage B. Date: 2026-10-02. Baseline: `5dc6819` (R2 closed).
This is a public API and contract addition, recorded here as `AGENTS.md` rule 5
requires. The default is unchanged.

## Change

Before M2 a rational edge had one denominator, `Q = 1 + Σ b_k z^k`, with the relative
pole guard: `|Q| <= ε(1 + Σ|b_k z^k|)` threw `std::domain_error` on the CPU and set
status bit 2 on the GPU. A single SGD step that put a denominator root on a training
sample therefore ended training, with no way to recover.

`RationalConfig` gains a typed policy (`include/kan/rational.hpp`):

```cpp
enum class DenominatorPolicy { Guarded, Absolute, Smooth };
struct RationalConfig { ...; double epsilon = 1e-8;
                        DenominatorPolicy denominator_policy = DenominatorPolicy::Guarded; };
```

With `S(z) = Σ_{k=1..n} b_k z^k`, the three policies are:

| Policy | Q | g = dQ/dS | Pole handling |
|---|---|---|---|
| `Guarded` (default) | `1 + S` | 1 | relative guard: `domain_error` / GPU status 2 (unchanged) |
| `Absolute` | `1 + abs(S)` | `sign(S)`, with `sign(0) = 0` | none needed: `Q >= 1` |
| `Smooth` | `1 + S^2` | `2S` | none needed: `Q >= 1` |

`Absolute` is the "safe PAU" denominator of Molina, Schramowski and Kersting,
*Padé Activation Units* (2019). Python gets `kan.DenominatorPolicy.GUARDED / ABSOLUTE / SMOOTH`
(a `py::native_enum`, so it is a real `enum.Enum`) and `RationalConfig.denominator_policy`.

### Decisions

- **A typed enum inside `RationalConfig`, not a new carrier.** The policy changes only
  `Q` and its derivatives. Parameter layout, shapes, the L2 penalty, SGD, the setters
  and the resident parameter layout are identical for all three policies. As
  R2 foresaw, `RationalEdges`, `RationalPlan` and the VJP code are the only places that
  change. The config is copied into the carrier, so `operator==`, snapshots,
  `download_parameters` and Python all carry the policy without extra code. An unknown
  enumerator is rejected by `validate_rational` ("invalid rational configuration").
  That function runs on every config entry point: the Layer constructor,
  `set_carrier`, `evaluate_rational` and the Python constructor (resident plans copy
  configs from validated layers).
- **The default stays `Guarded`.** Switching it would be a contract change, and it
  fails on three counts:
  1. *Represented function.* A safe policy changes the function class, not just the
     guard: `Q >= 1` cannot represent a sign-changing denominator. Coefficients
     supplied as Padé approximants (the contract's [1/1] exponential `a = {1, 0.5}`,
     `b = {-0.5}`) describe a `Guarded` edge, and under `Absolute` they would silently
     describe another function.
  2. *Zero initialization.* Rational layers are zero-initialized (`P = 0, Q = 1`). At
     `b = 0`, `S` vanishes identically, so both safe policies give `dr/db = 0` for every
     sample. The denominators would never leave zero (see the mathematics below).
     Switching the default would turn every default-constructed rational layer into a
     polynomial layer without any error.
  3. *Equivalence.* The golden dumps, frozen benchmark checksums and all M4 tests
     encode `Guarded`. Keeping it lets M2 prove bit identity rather than argue around
     it.

  The safe policies are opt-in. They are the recommended choice for training from a
  nonzero denominator initialization (for example a PAU-style fit).
- **`epsilon` is still validated for every policy** but used only by `Guarded`. One
  rule is simpler than a policy-dependent one. Switching the policy of an existing
  config never makes it invalid.
- **Compile-time dispatch.** The shared formulas are templates on the policy:
  `rational_horner<P>`, `rational_pole<P>`, `rational_edge<P>` and
  `rational_denominator_vjp<P>` in `src/detail/rational_formulas.hpp`, the single
  host/device source per R3. `if constexpr` removes the code of the other policies.
  - **CPU.** `forward` and `backward` of `RationalEdges` dispatch once per call
    (`visit_denominator_policy`) into per-policy loop function templates.
    `evaluate_rational_trusted<P>` is explicitly instantiated for each policy.
  - **CUDA.** `rational_forward_kernel<P>` and `rational_parameter_kernel<P>` are
    instantiated per policy, as C4 did per basis family. `rational_input_kernel` is
    policy independent.
- **GPU gain cache.** The parameter kernel recomputes VJPs from cached `P` and `Q`. The
  safe policies also need `g`: `sign(S)` cannot be recovered from `Q`, and `2S` from
  `sqrt(Q-1)` would lose sign and precision. So `RationalPlan` reserves one more
  edge-major buffer `gains` (8 bytes per sample and edge), after the existing three
  and only for safe policies. `Guarded` passes a null pointer, and its arena layout and
  size are unchanged.

## Mathematics

Let `z = (x - c)/s`, `P = Σ_{k=0..m} a_k z^k`, `S = Σ_{k=1..n} b_k z^k`, `Q = 1 + f(S)`,
`r = P/Q`, with `f(S) = S`, `|S|` or `S²` and `g = f'(S)`. By the chain rule,
`Q' = dQ/dz = g S'` and `∂Q/∂b_k = g z^k`. Then:

- `dr/dx = (P' - r Q') / (Q s) = (P'/Q - r g S'/Q) / s`
- `dr/da_k = z^k / Q` (independent of the policy)
- `dr/db_k = -(P/Q²) ∂Q/∂b_k = -r g z^k / Q`

`Guarded` (`g = 1`) reproduces the M4 formulas. `Smooth` is C^∞ in `x`, `a` and `b`.
`Absolute` is Lipschitz but not differentiable where `S = 0`.

**Subgradient at S = 0 (Absolute).** The one-sided derivatives in `b_k` are
`∓ r |z^k| / Q`. Its Clarke subdifferential is the interval between them, and
`sign(0) = 0` picks its midpoint, which is also the minimal-norm element. PAU's
reference implementation and PyTorch's `abs` autograd (`sgn(0) = 0`) use the same
convention. In `x`, `Q'` is then 0, so `dr/dx = P'/(Q s)`.
`tests/rational_policy_test.cpp::absolute_subgradient_is_zero_where_the_sum_vanishes`
checks both the convention and the one-sided finite differences (`+2` and `-2`, whose
midpoint is 0).

**Consequence: b = 0 is stationary under both safe policies.** At `b = 0`, `S ≡ 0` for
every input, so every `dr/db_k = 0`:
- for `Smooth`, `g = 2S = 0`, which is a genuine critical point;
- for `Absolute`, it is the subgradient convention.

Gradient descent therefore cannot leave `b = 0`, and a safe layer needs nonzero initial
denominators. The contract states this.

**No poles.** For `Absolute` and `Smooth`, `Q >= 1` holds for every finite `S`, so
`rational_pole<P>` is `false` at compile time. The guard is not evaluated, cannot
fire, and `epsilon` is ignored.

**Finiteness.** The checks remain on every intermediate:
- `S` and `S'` through Horner;
- `S²` and `1 + S²` (`Smooth` raises `overflow_error` when only `S²` overflows);
- `g`, `g S'` and every derivative intermediate.

For a finite `S`, `1 + |S|` cannot overflow.

**Log-space paths.** M4's representable-derivative paths carry over:
- *Absolute.* `g ∈ {-1, 0, 1}`, so `Q' = g S'` and `g × (guarded-form dr/db)` are exact,
  and the guarded log paths apply unchanged.
- *Smooth.* `Q' = 2 S S'` can underflow to a subnormal or zero while `r Q'/Q` is
  representable. `rational_edge` then uses `log|g| + log|S'|` with sign
  `sign(g) · sign(S')`. The `Smooth` denominator VJP has its own log path
  `log|P| + log|g| + k log|z| - 2 log|Q|`, with negative sign iff `P g z^k > 0`.

Both are tested, including negative `z`, odd `k` and a negative slope
(`representable_vjps_survive_underflowing_slopes`, `log_space_paths_with_negative_signs`).

- **`tests/rational_policy_resident_test.cpp` (3 cases).**
  - CPU/CUDA parity of output, input gradient, coefficient (with L2), denominator and
    bias gradients, and trained parameters over three SGD steps of a mixed
    rational/Chebyshev/rational network. This covers all three policies and degrees
    `0/0, 0/3, 4/1, 3/2, 16/16`, with mixed-sign denominators so that `S` changes
    sign. Workspace allocation counts are unchanged.
  - Resident SGD through the pole.
  - GPU overflow reporting (for both policies, and for `Smooth` when only `S²`
    overflows).
- **`tests/m4_python_test.py::M2DenominatorPolicy` (4 cases).** Enum round trip and
  default, closed forms plus finite differences, SGD through a pole, and resident parity
  for every policy, including the policy surviving `download_parameters`.

**SGD regression.** One 1→1 edge (`m = 0`, `n = 1`) starts at `a = 1`, `b = -1/2` and
trains on a single sample `x = 1` towards target 4 with rate 1/16. Under `Guarded`, the
first step gives `y = 2`, `∂L/∂b = 8` and `b ← -1/2 - 8/16 = -1` exactly, so the
next forward has `Q = 0`:
- CPU: `domain_error`;
- resident: `domain_error`;
- Python: `ValueError`.

Under `Absolute` and `Smooth`, the same initial point and rate train for 200 steps with
finite losses, and the final loss is below `1e-6` of the first. The resident trajectory
equals the CPU one to `5e-10`.

| m3 | 0.973 | 1.001 | 1.012 | — |

**A regression found and fixed.** The first ABBA run, on `b83fc0e`
([M2-bench/initial/](M2-bench/initial/)), measured m4 CPU at **1.108**: [1/1] was
unchanged, but [3/2] and [6/4] were 8–15% slower. There were two causes:

1. The per-policy loops ran inside `[&]` lambdas. MSVC does no type-based alias
   analysis, so the loop bounds and degrees captured by reference were reloaded after
   every gradient store.
2. The guarded denominator VJP computed its log-path sign flag unconditionally.

Commit `16aa776` moves the loops into function templates whose bounds are locals, and
restores the guarded VJP textually. With the profiling harness (CPU best-of-15 per
step, alternating builds), the result was [1/1] −11%, [3/2] +0.3…1%, [6/4] ±0%. The
final ABBA run above gives m4 CPU **0.954**.

**Resident (\*).** The `Guarded` device code issues the same instructions as the base
(Nsight Compute below). The m4 resident/transfer ratios are WDDM noise, with a second
agent sharing the GPU:
- the same build measured m4 case 7 at 11.4 and 31.7 ms, and case 11 at 19.8 and
  42.9 ms, across runs;
- [1/1] full steps alternated four times gave 6.83/6.83/6.83/6.12 ms best (base)
  against 6.35/6.83/6.52/6.83 ms (M2), with identical checksums
  ([policy-steps.txt](M2-bench/policy-steps.txt)).

Percentages are relative to `Guarded`. Executed instructions of `Guarded` equal the
base exactly: for example, the [3/2] parameter kernel executes 164 403 792 in both, and
the [6/4] forward 198.2 M. † The first [3/2] pass measured `Guarded` at 6996 µs with
equal instructions; two further alternating passes measured 6329.9/6329.7 (base) and
6329.6/6328.9 µs (M2). The outlier was interference.

Interpretation:

- **Forward.** `Absolute` drops the guard bound (`Σ|b_k||z|^k`) and the pole test, and
  adds `|S|` and a sign. At [6/4] the guard costs more than the sign, so `Absolute` is
  4% faster; at [1/1] the extra gain store (one more 8-byte write per sample and edge)
  dominates (+8%). `Smooth` adds `S²`, the doubled gain and its guards, at 66 instead
  of 59 registers. That lowers the theoretical occupancy of the `Smooth` forward from 4
  to 3 blocks of 256 threads per SM (32 → 24 warps). Capping it with
  `__launch_bounds__(256, 4)` was tried and rejected
  ([ncu-launch-bounds-rejected.csv](M2-bench/ncu-launch-bounds-rejected.csv)):
  - every instantiation, including `Guarded`, was recompiled with 64 registers and a
    different instruction count;
  - `Smooth` got no faster ([1/1] 5513 µs, [6/4] 13557 vs 12653 µs).

  More resident warps do not help this FP64-heavy kernel on GA102 (FP64:FP32 = 1:64),
  so occupancy is not its limiter.
- **Parameter VJP.** The safe policies read the cached gain for each denominator
  parameter. `Smooth` also executes 4.4–4.8% more instructions (the scaled product and
  its log-path tests), and its +14–26% time is the additional cache stream in a kernel
  that is already latency bound. In this kernel one warp per parameter rescans all
  samples of its edge, which is backlog **C8** (one warp per edge accumulating all
  m+n+1 sums). C8 will remove the per-parameter rereads of `z`, `P`, `Q` and `g`
  together, for all policies, so the gain read is left to it rather than special-cased
  here.
- **Full steps** ([policy-steps.txt](M2-bench/policy-steps.txt)). Resident best:
  - [6/4]: 19.25 (base) / 20.88* (Guarded, single noisy run; 19.19 in the earlier
    run) / 19.05 / 19.88 ms;
  - [3/2]: 11.31 / 11.35 / 11.60 / 11.98 ms.

  `Smooth` costs ≈3–6% per resident step and `Absolute` 0–2%. CPU: `Smooth` is the
  slowest (+11–27% per step, from its additional guarded intermediates); `Absolute`
  ranges from 0% to +16%. Both are opt-in costs; the default path is unchanged.

## Review

An independent `cpp-reviewer` pass over `2cb43d3..b83fc0e` (read-only, while the
benchmarks ran) found no CRITICAL or HIGH issues. It checked:

- the S/S' Horner by hand for n = 0, 1, 2;
- every sign of the log-space paths;
- the textual identity of the `Guarded` instantiation;
- the gain-buffer layout and the null pointer for `Guarded`;
- the consistency of the cached gain between the forward and parameter kernels;
- enum validation at every config entry point;
- the retained overflow semantics.

Its findings:

- **Fixed (MEDIUM):** there was no CTest-level bit-identity check for the default
  policy. Added `default_policy_is_bit_identical_to_pre_m2_formulas` with hex values
  printed by `5dc6819`. The golden dumps cover CPU, Layer and resident paths byte for
  byte.
- **Fixed (MEDIUM):** `docs/CONTRACT.md` now has the subsection "Denominator policy
  (backlog M2)" in the rational section, plus the Python field and the PAU reference.
- **Fixed (LOW):** `visit_denominator_policy` threw nothing for an unvalidated value; it
  now throws `logic_error` instead of silently falling back to `Guarded`.
- **Fixed (LOW):** missing tests for `set_carrier` with an invalid policy, for
  negative-sign log paths (negative `z`, odd `k`, negative slope), and for resident
  `Smooth` overflow when only `S²` overflows. The resident overflow comment was
  corrected: for a finite `S`, `1 + |S|` cannot overflow.
- **Fixed (LOW):** the `RationalHorner::gain` comment now states that it is unused (0)
  for `Guarded`.
- **Accepted (LOW):** the `Absolute` denominator VJP still evaluates the guarded form
  when `g = 0`, so an overflowing `-r z^k/Q` raises even though the result would be 0.
  This keeps the contract that every derivative intermediate is finite, and matches the
  forward pass.
- **Noted:** a resident `Guarded` pole followed by a safe network in the same process
  is not tested separately. Each `ResidentNetwork` owns its stream and status, and
  `rational_policy_resident` already runs both in one process.

The CPU performance regression above was found by the ABBA run, not by the review, and
was fixed in the same pass.

## Open points

- **C8** should restructure `rational_parameter_kernel` for all policies; the safe
  policies' cached-gain reads are then amortized per edge.
- **M4 (initializers)** should provide a nonzero denominator initialization for safe
  policies (for example a PAU-style fit of a reference activation), since `b = 0` is
  stationary under them.
