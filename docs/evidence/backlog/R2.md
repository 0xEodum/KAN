# R2: typed edge carriers instead of the `rational_` flag

Backlog item R2 (P0), stage B. Date: 2026-10-02, branch `cpp-foundation`.
This is a public API and contract change, recorded here as `AGENTS.md` requires.
Baseline: HEAD `4a73811` (R1 closed).

## Change

Before R2, `Layer` held a `BasisConfig`, a `bool rational_`, a `RationalConfig`,
`denominators_` and `coefficients_`, and branched on `rational_` in `forward`,
`backward`, `sgd`, `validate_state`, `terms`, the accessors and the setters; the
trainable RBF added a runtime branch inside the backward inner loop. The resident
executor carried `rational` and `trainable` flags in its `Layout` and branched on them
in construction, forward, backward, SGD and both downloads. A third nonlinear family
(M5 PQC/Fock) would have added a third branch everywhere.

Now a layer holds dimensions, a bias and exactly one carrier
(`include/kan/carrier.hpp`):

```cpp
struct BasisEdges        { BasisConfig basis;        std::vector<double> coefficients; };
struct TrainableRbfEdges { TrainableRbfConfig basis; std::vector<double> coefficients; };
struct RationalEdges     { RationalConfig config;    std::vector<double> coefficients, denominators; };
using Carrier = std::variant<BasisEdges, TrainableRbfEdges, RationalEdges>;

struct TrainableRbfGradients { std::vector<double> centers, log_widths; };
struct RationalGradients     { std::vector<double> denominators; };
using NonlinearGradients = std::variant<std::monostate, TrainableRbfGradients, RationalGradients>;
```

`LayerGradients` is `{input, coefficients, bias, nonlinear}`.

### Decisions

- **`std::variant` + one `std::visit` per call, not a virtual interface.** It
  matches R1's variant configuration, keeps carriers value types (copy, `==`,
  atomic replacement by swap) and compiles each carrier's loops separately, so no
  hot loop dispatches per element. `src/layer.cpp` contains no per-carrier code
  except the rational constructor; each operation is one `std::visit` into the
  overloads declared in `src/carriers/edge_ops.hpp`.
- **Every carrier has a per-edge `coefficients` tensor** `(outputs, inputs, terms)`:
  linear coefficients or rational numerators. It is the tensor the coefficient L2
  acts on, so `coefficients()`, `set_parameters`, the coefficient SGD update and
  `regularization` are carrier independent. Everything else a carrier owns is
  nonlinear and has its own VJP and update (`check_gradient`, `update_nonlinear`).
- **One linear engine.** `src/carriers/linear_engine.hpp` is the expansion
  `Phi: R^I -> R^(I*K)` (one row of `I*K` values and derivatives per sample) and the
  dense contraction `Y = Phi * C^T + b` with its VJP (`contract`, `contract_vjp`).
  `BasisEdges` uses it alone; `TrainableRbfEdges` uses the same engine and adds its
  center/log-width VJPs through a compile-time hook inside `contract_vjp`, which
  replaces the former runtime `if (!gradient.centers.empty())` in the inner loop.
  C2 replaces `contract`/`contract_vjp` (per row now) by GEMM over blocks of rows in
  one place; on the device the same split is `basis_kernel` (expansion) and
  `forward_kernel`/`input_kernel`/`parameter_kernel` (contraction), wrapped by
  `ExpansionPlan`.
- **The trainable RBF is a nonlinear carrier on the linear engine**, as the backlog
  classifies it: its basis parameters are trainable, but its forward is still the
  expansion and contraction, so it reuses that code instead of copying it.
- **`BasisEdges` rejects a `TrainableRbfConfig`.** The configuration variant is R1's
  public type; a narrower "fixed families" variant would have needed conversions
  between variants. `Layer(in, out, BasisConfig)` maps `TrainableRbfConfig` to
  `TrainableRbfEdges`, and `set_carrier` rejects the invalid combination.
- **Family operations are free functions** in `include/kan/families.hpp`:
  `insert_knot`, `adapt_grid`, `set_rbf_parameters`, `set_rational_parameters`. They
  read the carrier they need, build the replacement and commit it through
  `Layer::set_carrier`, which revalidates the whole layer; Boehm insertion and
  the grid adaptation are moved unchanged into `src/families.cpp`.
  `Network::insert_knot/adapt_grid` remain as one-line forwards.
- **`Layer::set_carrier(carrier[, bias])`** is the single validated mutation point for
  carrier-specific state: configuration, shapes for the layer's dimensions, finite
  coefficients and nonlinear parameters, then atomic replacement.
- **`set_parameters` is generic.** It sets the per-edge coefficients of any carrier,
  including rational numerators (it used to reject rational layers). This keeps the
  setter symmetric with `coefficients()`.
- **Resident executor.** `Layout` with `rational`/`trainable` flags is replaced by
  `Plan = std::variant<BasisPlan, TrainableRbfPlan, RationalPlan>`; each plan owns its
  workspace offsets and has `reserve_workspace`, `upload_carrier`, `run_forward`,
  `run_backward`, `validate_candidates`, `download_nonlinear` and `download_carrier`
  overloads. Shared device state is a `Context` base of `Impl`. Kernels, launch
  configurations, arena reservation order and parameter layout
  `[coefficients | bias | nonlinear]` are unchanged (the first 215 lines of
  `src/resident.cu` differ from `4a73811` only by two `#include`s).
  `download_parameters` builds each trained carrier and commits it with
  `set_carrier(carrier, bias)`.
- **Python mirrors the split.** `Layer.carrier` returns a read-only snapshot
  (`kan.BasisEdges`, `kan.TrainableRbfEdges`, `kan.RationalEdges`); family operations
  are module functions; `Layer.terms` is new. `LayerGradients.centers/log_widths/
  denominators` stay as arrays (empty for other carriers): they are output
  snapshots and keep the gradient API stable.
- **Adding a carrier (M5).** A new alternative in `Carrier` and `NonlinearGradients`,
  its overloads in `edge_ops.hpp` (a `nonlinear_of` specialization included), a
  resident plan with the plan overloads, and a Python snapshot class. `Layer`,
  `Network` and the SGD/L2 protocol do not change.

`RationalConfig` gains a defaulted `operator==` (needed for carrier equality).

## Migration

| Before | After |
|---|---|
| `layer.is_rational()` | `std::holds_alternative<kan::RationalEdges>(layer.carrier())` |
| `layer.basis()` | `std::get<kan::BasisEdges>(layer.carrier()).basis` (fixed families) |
| `std::get<kan::TrainableRbfConfig>(layer.basis())` | `std::get<kan::TrainableRbfEdges>(layer.carrier()).basis` |
| `layer.rational_config()` | `std::get<kan::RationalEdges>(layer.carrier()).config` |
| `layer.denominators()` | `std::get<kan::RationalEdges>(layer.carrier()).denominators` |
| `kan::basis_size(layer.basis())` | `layer.terms()` |
| `layer.insert_knot(x)` / `layer.adapt_grid(s)` | `kan::insert_knot(layer, x)` / `kan::adapt_grid(layer, s)` (`#include <kan/families.hpp>`) |
| `layer.set_rbf_parameters(c, w)` | `kan::set_rbf_parameters(layer, c, w)` |
| `layer.set_rational_parameters(a, b, bias)` | `kan::set_rational_parameters(layer, a, b, bias)` |
| `layer.set_parameters(a, bias)` on a rational layer: `invalid_argument` | sets the numerator coefficients and bias |
| `gradients.centers` / `.log_widths` | `std::get<kan::TrainableRbfGradients>(gradients.nonlinear).centers` / `.log_widths` |
| `gradients.denominators` | `std::get<kan::RationalGradients>(gradients.nonlinear).denominators` |
| Python `layer.basis`, `layer.is_rational`, `layer.rational_config`, `layer.denominators` | `layer.carrier.basis`, `isinstance(layer.carrier, kan.RationalEdges)`, `layer.carrier.config`, `layer.carrier.denominators` |
| Python `layer.insert_knot(x)`, `layer.adapt_grid(s)`, `layer.set_rbf_parameters(c, w)`, `layer.set_rational_parameters(a, b, bias)` | `kan.insert_knot(layer, x)`, `kan.adapt_grid(layer, s)`, `kan.set_rbf_parameters(layer, c, w)`, `kan.set_rational_parameters(layer, a, b, bias)` |

New errors: `set_carrier` with a wrong shape raises "carrier coefficient shape
mismatch"; SGD with a gradient of another carrier raises "nonlinear gradient type
does not match the carrier". All other messages are unchanged.

Tests use small accessors in `tests/support/families.hpp` (`test::trainable`,
`test::denominators`, `test::centers`, `test::log_widths`, `test::rational`) so their
assertions are unchanged. One assertion changed meaning: `m4_layer_test` used to
require that `set_parameters` rejects a rational layer; it now requires the
generic setter to accept the numerator shape and reject a wrong one. The
`basis()`/`rational_config()` rejection checks became carrier-type checks.

`docs/CONTRACT.md` gains the section "Edge carriers (R2)" and its M3/M4/Python
paragraphs use the new names; `README.md` examples are updated.

The default golden mode covers CPU basis/rational evaluation and the resident
executor. R2 mainly rewrites CPU `Layer`, which that dump did not exercise, so the
harness gained `--layers`: the five resident fixture networks run on the CPU for three
forward / backward / L2 / SGD steps (outputs, all gradients including nonlinear ones,
penalties, trained parameters and knots), plus knot insertion, grid adaptation and the
RBF and rational setters, and the guard and family-operation exceptions with their
messages. The harness compiles against both APIs (`__has_include("kan/families.hpp")`
selects small adapters), so the baseline and R2 run the same fixtures. Both dumps were
produced by builds of the same `golden.cpp`; the default-mode dump of that harness on
`4a73811` is identical to the one of the R1 harness.

Bit identity holds because every accumulation keeps its operation sequence: forward
outputs start at the bias and add `C[o,j]*Phi[j]` for `j = i*K+k` ascending (before:
the same order through `i` then `k`); the input VJP accumulates `(u*C)*Phi'` in `o`,
`k` order from 0; coefficient VJPs accumulate over the batch; RBF center/log-width
VJPs accumulate `(u*C)*partial` in `b, i, o` order; the rational loops are moved
unchanged. Basis evaluation order (and so which guard throws first) is unchanged.
Neither MSVC `/fp:precise` nor GCC `-ffp-contract=off` reassociates or contracts the
reduction loops.

## Benchmarks

Frozen benchmarks (`m2/m3/m4_benchmark --backend all --warmups 2 --repeats 7`) in
ABBA order per suite (base, r2, r2, base). Each cell is the geometric mean over cases
of the pooled-median ratio r2/base ([compare_bench.py](compare_bench.py); raw CSVs
and [summary.csv](R2-bench/summary.csv) in [R2-bench/](R2-bench/)).

| Suite | CPU | Resident | Transfer | M1 host |
|---|---|---|---|---|
| m2 (polynomial, Fourier, Gaussian) | 0.462 | 0.702* | 0.854* | 0.987 |
| m3 (B-spline, Mexican hat, trainable RBF) | 0.661 | 0.919* | 0.942 | — |
| m4 (rational) | 0.933 | 1.054* | 1.001 | — |

**CPU.** The expansion + contraction engine makes the CPU basis path 1.5–2.6× faster
(m2 case 3: 198 → 86 ms; m3 case 3: 247 → 132 ms): the forward contraction is now a
contiguous dot product per output over the sample's `Phi` row (a GEMV), where the old
loop walked `C` per input with the output accumulator in memory. The operation order
is the same, so results are identical. m4 (rational) is 7% faster; its loops are
unchanged, the gain comes from the leaner per-call dispatch.

**Resident (\*).** The device code is unchanged, so these ratios are noise of the
`--backend all` runs under WDDM: m2 cases 11/15/19/23 measured 5.9–16.3 ms in the
first baseline run and 7.2–11.7 ms in the last, against 2.3 ms for R2; m4 case 3
measured 7.5 and 29.2 ms in the two R2 runs. Rerun in isolation, alternating
builds (`--backend resident --case N --repeats 15`, three rounds), the cases agree:
case 11 2.52 vs 2.30 ms, case 15 2.27 vs 2.06–2.26 ms, case 23 2.41 vs 2.41 ms
(base vs R2). The small host-side gain is consistent with no longer rebuilding the
basis view and re-reading the layer configuration on every launch.

**Profiling (AGENTS.md rule 6).** Nsight Systems on resident case 11 of each suite
(the largest topology), base vs R2 ([nsys-kernels.csv](R2-bench/nsys-kernels.csv)):
every kernel has the same launch count and the same median time within 0.4%
(e.g. `rational_parameter_kernel` 2662.5 → 2663.3 µs, `nonlinear_partial_kernel`
502.9 → 505.2 µs, `basis_kernel` 146.0 → 146.0 µs). The kernels themselves are
byte-for-byte the same source, so no Nsight Compute rerun was needed. The profile
confirms the known bottlenecks, which belong to later items: the naive contraction
kernels (`input_kernel`, `parameter_kernel`, `forward_kernel`: C2) and the rational
forward/parameter kernels, ~99% of m4 GPU time (C6–C8).

## Review

An independent `cpp-reviewer` pass over `58929ac` (read-only, while the benchmarks
ran) found no CRITICAL or HIGH issues. It verified operation by operation that every
accumulation keeps its order and association, that setters, `set_carrier`, SGD, the
family operations and `download_parameters` validate before committing, that no span
or reference outlives the carrier it points into, and that the resident executor
issues identical launches with an identical arena layout. Its findings:

- **Fixed (MEDIUM):** the expansion scratch (`I*K` per buffer instead of `K`) was
  allocated even for batch 0, which the resident constructor uses as a shape check.
  Carriers now return before allocating.
- **Fixed (MEDIUM):** `with_carrier` mapped plans to carriers through a
  `std::conditional_t` chain that a new carrier would have to extend; each plan now
  names its `edges_type`.
- **Fixed (MEDIUM):** `set_parameters` copied the whole carrier; it now swaps only the
  coefficient vector. Its new acceptance of rational layers is the documented
  semantic change above (Decisions, Migration).
- **Fixed (LOW):** `Impl` derived from a type in an anonymous namespace; the shared
  device state is now the named `ResidentContext`.
- **Fixed (LOW):** comments on the moved destination buffers of asynchronous
  downloads, and a Python docstring stating that `Layer.carrier` is a copying snapshot.
- **Accepted (LOW):** on a moved-from or wrong-carrier layer, the family operations
  report their own message (for example "knot must be strictly inside a spline
  domain") instead of "layer is uninitialized or moved from"; the exception type
  (`invalid_argument`) and the unchanged layer are as before. The Python setters
  check the carrier type before array shapes.
- **Noted:** besides alternatives and overloads, a new carrier also needs its
  constructor mapping (`Layer(in, out, Config)`) and the Python snapshot class; both
  are listed under "Adding a carrier" above. MSVC has no explicit FMA flag (pre-R2,
  backlog C10).

After the fixes (`6ef39f1`): 21/21 CTest (MSVC + CUDA + Python), 13/13 GCC with no
warnings, both golden dumps unchanged (`B796A897…`, `C1F44D97…`). A CPU spot check
(`--backend cpu --case 3`) gave identical checksums and the same times as the ABBA
run: m2 196.1 → 87.0 ms, m3 233.0 → 132.2 ms, m4 622.6 → 589.5 ms. The fixes do not
touch device code or numerical loops, so the frozen ABBA results of `58929ac` stand.

## Open points for later items

- **C1/C2.** The engine is per row: `contract` is a GEMV per sample and
  `contract_vjp` fuses the coefficient and input VJPs per sample. C2 replaces both
  by GEMM over row blocks (CPU) and cuBLAS on the device behind `ExpansionPlan`; the
  summation order there will change, so bit identity against this dump ends at C2
  (tolerance-based parity, as the contract already states for CPU vs GPU). C1 will
  template the carriers on `Scalar`.
- **M1 (input map).** A typed input map fits as a separate layer kind or as a
  pre-expansion step of `BasisEdges`; it must not become a flag in `Layer`.
- **M2 (safe denominator).** A denominator policy belongs in `RationalConfig` and
  `rational_formulas.hpp`; `RationalEdges`, `RationalPlan` and the VJP code are the
  only places to change.
