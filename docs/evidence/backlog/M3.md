# M3: optional SiLU residual branch — phase 1 (CPU, initializers, Python) and phase 2 (resident CUDA)

Backlog item M3 (P1), stage B. Date: 2026-10-09. Base: `8c489e6` (C6–C8 closed).
This is a public API and contract addition, recorded here as `AGENTS.md` rule 5 requires.
(Not to be confused with milestone M3, [../M3.md](../M3.md).)

**Phase 1** delivers the branch on the CPU `Layer`/`Network`, the shared host/device
formulas, the initializers and the NumPy bindings; the resident executor rejected the branch.
**Phase 2** ([below](#phase-2-resident-cuda)) executes it on the resident executor in every
precision and removes the rejection. Closing M3 in [BACKLOG.md](../../BACKLOG.md) is the
coordinator's step.

**The default is unchanged.** Constructors create layers without the branch. Golden dumps in
both modes, the nine pinned M4 initializer digests and every pre-existing test are unaffected.

## Problem

B-splines have compact support and are exactly zero, with zero input gradient, outside
it. Gaussian RBF and Mexican-hat bases instead have decaying tails; sufficiently far
from their centers, values and derivatives can underflow to zero in floating-point
arithmetic. If every carrier derivative vanishes at a layer's inputs, its input
gradient is zero and the preceding layers receive no gradient through it. The original
KAN adds a possible gradient path with a base branch,
`phi(x) = w_b·silu(x) + w_s·spline(x)`; this path depends on its weights, inputs and upstream.

The M4 evidence showed the related consequence. pykan-style `NoiseInit` without that branch
leaves a five-layer network at the mean-predictor saddle (MSE 0.1205) on every carrier.

### Decisions

- **The branch belongs to the layer and is carrier-independent.** It is opt-in. It lives on
  `Layer`, not in a carrier, so `set_carrier`, `set_parameters`, `insert_knot`, `adapt_grid`,
  `set_rbf_parameters` and `set_rational_parameters` leave it untouched (tested). A carrier
  needs no new code to gain the branch.
- **Order of summation.** The carrier's output is computed first, on its unchanged code path.
  Then `r = Σ_i w[o,i]·silu(x[b,i])` is accumulated from 0 in ascending i, and `y += r`.
  - Backward runs after the carrier's VJPs:
    - `dw[o,i] = Σ_b u[b,o]·silu(x[b,i])`, ascending b;
    - `dx[b,i] += silu'(x[b,i])·t`, with `t = Σ_o u[b,o]·w[o,i]` ascending o.
  - silu and silu' are evaluated once per (sample, input), not once per edge.
  - Intermediates are not guarded one by one. A finite product or sum that overflows ends
    nonfinite, never finite again, because there are no divisions. Every result is then
    checked (`std::overflow_error`), the same argument the C7 Horner guards use.
- **The formulas cannot overflow.** With `e = exp(-|x|)` ∈ (0, 1]:
  - for `x >= 0`, `σ = 1/(1+e)` and `1-σ = e/(1+e)`;
  - for `x < 0`, `σ = e/(1+e)` and `1-σ = 1/(1+e)`;
  - `silu = x·σ` and `silu' = σ·(1 + x·(1-σ))`.

  exp never overflows, `1-σ` is never formed by cancellation, and `|x(1-σ)| <= |x|`. So no
  intermediate is nonfinite for any finite x, in double or float. The test uses a guard that
  throws, at ±1e3, ±709, ±746, ±1e300, ±DBL_MAX, ±DBL_MIN, ±denorm_min and −0 for double, and
  ±88, ±100, ±104, ±1e30, ±FLT_MAX, ±FLT_MIN for the float instantiation on the host. It
  checks `silu(DBL_MAX) = DBL_MAX` with `silu' = 1`, and `silu(−DBL_MAX) = −0` with `silu' = 0`.
- **The L2 penalty includes the branch weights,** as the coordinator decided. The value is
  `λ/2·(Σc² + Σw²)` and the gradient is `λ·w`. The coefficient loop is unchanged and runs
  first, so the no-branch value stays bitwise identical (golden `--layers`). Denominators,
  RBF centers/widths and bias stay unpenalized.
- **SGD.** `gradients.residual` must have `outputs*inputs` entries when the branch is present
  and be empty otherwise. Everything is validated before anything is committed (tested on a
  layer and a network).
- **Initializers.** A layer's branch presence is kept. A layer without the branch is
  initialized exactly as before. The residual draws come last, so the coefficient and
  denominator draws of a layer with the branch are identical to those without it (tested).
  - `NoiseInit` draws pykan's `scale_base = (mean + spread·U[-1,1))/√in`. The Normal variant
    is `(mean + spread/√3·z)/√in`, with equal mean and variance and portable arithmetic only.
  - `VarianceScaling` sets `w = 0`, preserving the carrier's second-moment guarantee
    under the reference measure, in expectation over initialization. Zero weights do
    not force `dw = Σ u·silu(x)` to vanish: it is nonzero in the tested cases on all
    carriers, but can be zero for other inputs or upstream. The branch's contribution
    to `dx` is zero at initialization and can become nonzero after a weight update.
  - Carrier, bias and branch are committed together on a copy of the layer.
- **GCC 15 false positive.** Adding *any* member to `Layer` made GCC 15.2 `-O3 -Wall` report
  `-Wmaybe-uninitialized` inside libstdc++'s `variant` cleanup path. It fires where
  `std::vector<NetworkLayer>` is copied, in `Network::sgd` and `initialize(Network&)`. A
  bisection with a plain vector member reproduced it, and with no member it did not.
  `Layer(const Layer&)` is now defined out of line (`= default` in `layer.cpp`), which
  removes the warning without a pragma. The other special members stay inline defaults.

### pykan comparison (master `ecde4ec`, `kan/KANLayer.py`, `kan/MultKAN.py`)

pykan computes the edge as `y = scale_base·base_fun(x) + scale_sp·spline(x)`, with
`base_fun = SiLU`. It initializes
`scale_base = scale_base_mu/√in + scale_base_sigma·(2·rand−1)/√in`, with MultKAN defaults
μ = 0 and σ = 1. `NoiseInit` reproduces this exactly in distribution, with the defaults
`residual_mean = 0` and `residual_spread = 1`.

We implement `scale_base` only. pykan's trainable `scale_sp` multiplies the spline, so it is
a reparametrization of the carrier's linear coefficients, and its initial value `1/√in` is
already folded into the `NoiseInit` amplitude (M4). Two more pykan elements are absent:
pykan's per-edge `mask` (pruning) and its `sb_trainable`/`sp_trainable` freezing flags.
Neither is part of M3. The generator is SplitMix64, not torch's.

## Tests

`tests/residual_test.cpp` (18 cases):

- **Finite differences (h = 1e-6, tol 3e-7)** of the input, coefficient, bias, residual,
  center, log-width and denominator VJPs. This covers:
  - single layers with the branch, for Chebyshev, B-spline, trainable RBF and rational
    (Smooth) carriers;
  - a 3-layer mixed network (rational + trainable RBF with the branch, B-spline without);
  - a 4-stage network with Tanh maps.
- **Forward order.** The output equals the carrier output plus the ascending-i sum, to 1e-15.
- **Motivation, single layer.** B-spline, fixed Gaussian RBF and trainable RBF layers get
  inputs at 45, −41, 60 and −52, outside [−1, 1] and at least 80 widths from every center.
  - The carrier output is exactly the bias.
  - The input gradient is exactly 0 without the branch.
  - With the branch it is nonzero and equals `silu'(x)·Σ_o u·w`.
- **Motivation, two layers.** Layer 1 is a B-spline on in-domain inputs, with bias ±40. Layer 2
  is a B-spline, Gaussian RBF or trainable RBF.
  - Without the branch, layer 1's coefficient, bias and input gradients are exactly 0.
  - With the branch on layer 2 only, they are nonzero.
  - Layer 1's own `residual` gradient stays empty.
- **Validation and semantics:**
  - `set_residual` validation (shape, empty, inf, NaN, nullopt) is atomic, and a moved-from
    layer is rejected;
  - the branch is preserved across every carrier replacement and failed replacement;
  - copies are independent;
  - SGD with the branch: mismatched, absent, extra, nonfinite or overflowing gradients are
    rejected atomically, and a layer without the branch rejects a gradient that has one;
  - the L2 value and gradient are checked on four carriers;
  - `Network` backward, SGD (including atomic failure) and regularization carry the field;
  - overflow raises `overflow_error`.
- **Initializers:**
  - the carrier draws are independent of branch presence;
  - the NoiseInit mean and variance (Uniform and Normal), spread 0 and the defaults;
  - field validation;
  - VarianceScaling gives zero weights with a nonzero gradient;
  - per-layer presence in `initialize(Network&)`;
  - three pinned digests: `1ef218a170c967fd`, `3b6cb65c8b613b2f`, `af64dc9297fd02da`.

`tests/residual_formula_test.cpp` (4 cases): values and derivatives against an independent
long-double reference (4e-16 for double, 4e-7 for float), the derivative against central
differences, known values, and the extremes listed above. `silu_value` is bitwise equal to
`silu().value` everywhere.

`tests/residual_python_test.py` (6 cases):

- the property and setter;
- strictness: `TypeError` for float32 and for lists, `ValueError` for shape and nonfinite
  data, and atomicity;
- forward against `silu(x) @ w.T`;
- gradient shapes, including `(0,)` without the branch;
- `sgd` topology mismatch;
- L2;
- `insert_knot` and networks;
- the NoiseInit fields;
- CUDA builds: `ResidentNetwork` raises `ValueError`.

`tests/residual_resident_test.cpp` (CUDA, 2 cases): construction is rejected in FP64, FP32 and

**Reading.**

- With the branch, pykan-style NoiseInit leaves the saddle on every carrier. Without the
  branch it stays at exactly 0.1205 to 20 000 epochs.
- Escape is not fast:
  - the linear carriers sit near 0.12 for the first 100–300 epochs;
  - Chebyshev overshoots to 0.75 at epoch 300 with rate 0.03 before converging;
  - rational carriers need 3000–5000 epochs to leave.

  NoiseInit remains far slower than VarianceScaling, which is still the recommended training
  entry point.
- VarianceScaling with the branch (`w = 0`) trains like M4 without it. Rational edges reach the
  same 1–2e-3, while Chebyshev and B-spline end at a different but negligible level, because
  the branch weights move away from 0.
- The CTest asserts `< 0.5·variance` for NoiseInit + branch, at 3000 epochs for the linear
  carriers and 10 000 for rational, and `< 0.05·variance` for VarianceScaling + branch.

## Resident boundary (phase 1, superseded by phase 2)

`reject_residual(const Network&)` is a new helper in the file's anonymous namespace, next to
`finite`. It raises `std::invalid_argument("residual branch not supported by the resident
executor yet")` for any KAN layer with `residual()`. It is called at two points:

1. in `Engine::Engine`, right after the empty-network check, before the CPU validation
   forward, planning and any device allocation;
2. in `Engine::upload_parameters`, right after the layer-count check, before
   `with_matching_stage`. Otherwise the stage would match and `w` would be dropped silently.

Construction in every precision and `upload_parameters` therefore reject the branch. The
deprecated `kan::cuda::forward/backward(Layer)` adapters (`src/cuda.cu`) build a
`ResidentNetwork` and inherit the guard. A throwaway nvcc probe (sm_86, `--fmad=false`) compiled
`silu`/`silu_value` for float and double in a kernel with a status-recording guard and ran it
on the RTX 3090 at 0, ±1, ±30, ±1e300/±1e30 and ±DBL_MAX/±FLT_MAX: the guard status stayed 0,
double results equal the host bitwise and float results are within a few ulp (CUDA `expf`).
`include/kan/resident.hpp` is untouched; its comment
"Add lambda*c to coefficient/numerator VJPs" must gain `w` in phase 2. Resident
`download_stage_gradients` default-constructs `LayerGradients`, so `residual` is empty, which
is consistent while no resident layer has the branch.

## For phase 2 (resident executor; as planned in phase 1)

- **Formulas.** Use `#include "detail/residual_formulas.hpp"`:
  - `kan::detail::silu_value<Scalar>(x, guard)` for the forward pass;
  - `kan::detail::silu<Scalar>(x, guard)`, returning `SiluOf<Scalar>{value, derivative}`, for
    the backward pass;
  - `kan::detail::sigmoid<Scalar>(x)`, returning `{sigma, complement}`.

  All are `KAN_HOST_DEVICE KAN_FORCE_INLINE` and use `math::exp`/`math::abs` (float uses
  `expf`/`fabsf` on the device). Their guards never fire for finite x. In an FMA build
  (`KAN_CUDA_FMA=ON`), `1 + x·complement` may contract; parity builds use `--fmad=false`.
  Use `rounded_product` if bitwise CPU parity of `silu'` is required under FMA.
- **Gradient field.** `LayerGradients::residual`, layout `(outputs, inputs)`, empty without
  the branch.
- **Contract order.** Forward: the carrier output, then `+ Σ_i w·silu` (a separate sum). In
  cuBLAS terms this is `Y += S·Wᵀ` with `S = silu(X)` of shape (batch, inputs), and the
  device's summation order may differ: parity is tolerance-based. Backward:
  - `dW = Uᵀ·S`;
  - `dX += silu'(X) ⊙ (U·W)`, after the carrier's dX.
- **Parameter block.** Recommended ordering in a layer's device parameter block: the
  existing carrier block first (coefficients, nonlinear, bias, unchanged), then `w`
  (outputs×inputs) at the end. Existing offsets stay valid, and `ParameterImage`,
  `upload_parameters`, `download_parameters` and SGD/L2 extend by one trailing tensor. L2 on
  the device must add `λ·w`, and the plan must record branch presence so that a mismatched
  `upload_parameters` is rejected. S and silu'(X) can be computed once per forward and kept
  in the workspace, or recomputed in backward.
- **Tests to replace.** `tests/residual_resident_test.cpp` and the Python CUDA case assert the
  rejection; phase 2 replaces them with parity tests.

## Deviations and open questions (phase 1)

- **Deviations** from the brief, each justified above:
  - `Layer(const Layer&)` is out of line, for the GCC warning;
  - there is no Python `SiluResidual` class: the branch is exposed as arrays/`None`
    (`Layer.residual`, `Layer.set_residual`), which matches how carriers' parameters are
    exposed;
  - `LayerGradients.residual` without the branch has shape `(0,)`, like `denominators`;
  - the rational NoiseInit demonstration runs 10 000 epochs.
- **Owner question:** should the variance be split between the branches? VarianceScaling puts
  all of `gain²·Var_ref` into the carrier and sets `w = 0`. An alternative splits it, e.g.
  `E[(w·silu)²] = α·gain²·Var_ref/I` with α ∈ (0, 1) under the reference measure, which needs
  `E[silu(x)²]` per family measure. Not implemented; the recommendation is to keep `w = 0`
  unless a measured deep-training benefit appears.
- **Owner question:** should NoiseInit's default `residual_spread = 1` (pykan) be kept? It
  gives `|w|` up to `1/√in`, which dominates the small carrier noise at initialization: the
  network starts as a near-SiLU MLP, as in pykan.
- **Follow-up:** pykan's per-edge mask and branch-freezing flags are not part of M3.

### Design as implemented (`src/resident.cu`)

- **Parameter block** `[coefficients | bias | nonlinear | residual]` per KAN layer
  (`ParameterBlock::residual_count`, `residual()`). The SGD candidate kernel, the trainable-RBF
  width validation, the C9 commit/rollback kernel, `ParameterImage` uploads and
  `download_parameters`/`download_gradients` extend by the trailing tensor. Layers without the
  branch have the same blocks, and nothing new is reserved for them, so networks without the
  branch keep the arena byte for byte (the reservations are conditional).
- **Workspace** per layer with the branch: `S = silu(X)` and `silu'(X)`, `(capacity, inputs)`
  each, written in forward from one sigmoid (one exp), read in backward. The shared scratch
  grows to `capacity*inputs` for a branch (`U*W`), the shared partials to
  `(outputs*inputs+outputs)*tiles`; both only for networks with the branch. One 32 MiB cuBLAS
  workspace is reserved at the end of the arena when some branch takes a cuBLAS path at
  capacity (below). `workspace_allocations()` is unchanged.
- **Forward**, after the carrier's output:
  - `BasisEdges`/`TrainableRbfEdges`: `basis_kernel<Kind, Residual>` writes `S` and `silu'` in the
    pass that already reads `X`; on the small path `forward_dot_kernel<Residual>` accumulates
    `S[b,:]·W[o,:]` into the same lane partial sum before its single shuffle tree, then adds the
    bias; on the cuBLAS path the residual GEMM (`beta = 1`) runs between the carrier GEMM and
    `bias_kernel`, whose nonfinite check covers the sum. Extra launches: 0 (small) / 1 (cuBLAS).
    The `Residual = false` instantiations are the previous kernels.
  - `RationalEdges`: `silu_kernel`, then `residual_dot_kernel` (32-sample tile, lane = sample,
    S transposed and each warp's `W` row in shared memory) or cuBLAS + `check_kernel`.
- **Backward**, after the carrier's `run_backward` (so after `backward_finish_kernel` /
  `rational_input_kernel` write `dX`, and after the trainable-RBF reduction read the scratch):
  `dW` by `parameter_partial_kernel` over `S` (the expansion carriers' small-VJP rule) or cuBLAS
  (`beta = lambda` after copying `W`, as the carrier's `dC`); then `residual_finish_kernel`: tile
  sum + `lambda*W` and check of `dW`, and, if the layer's input gradient is needed,
  `dX += silu'(X)*t` with `t = sum_o U*W` inline or from a cuBLAS `U*W` into the scratch. An empty
  batch gives `lambda*W`; `input_gradient(j) == false` (the first layer in a training step)
  skips only `dX`. Extra launches: 2 (small) to 4.
- **Upload/structure:** presence compared in `with_matching_stage` ("residual branch presence");
  weights via `ParameterImage::put` (finite, FP32 representable); construction validates them
  with the coefficients' rules; `download_stage` sets the branch, `download_stage_gradients`
  fills `residual`.
- **FMA:** in the performance build nvcc may contract `1 + x*(1-sigma)` and the branch's
  multiply-adds; `rounded_product` is not used. No contract depends on the unfused rounding (the
  parity build is `--fmad=false`; all suites pass in both builds within the stated tolerances).

### Tests (`tests/residual_resident_test.cpp`, 7 cases, 34 s)

Fixtures: Chebyshev, B-spline, trainable RBF, rational Guarded and Smooth single layers (batch
7 of capacity 9); a mixed network with affine, LayerNorm and tanh maps, the branch on four
carriers and one layer without it; `wide` 192→192→3 Chebyshev at batch 600/301 (cuBLAS forward,
dW and `U*W` in both precisions, small forward in FP32 at 301); `medium` 64→80 Chebyshev K=7 at
400 (FP64 cuBLAS carrier + small branch before the bias); `rational_wide` 160→120 Smooth at

   residual) and SGD vs the FP64 CPU at the executor's parameters, at a full and a partial
   batch, with and without L2, FP64/FP32/TF32.
2. Empty batch: empty output and input gradient, `lambda*W` and the other L2 gradients.
3. `train_step` bitwise the eager sequence: `OutputGradient` (first layer with the branch: only

4. Rollback by the branch itself: a forward `S*W^T` overflow (`w = 1e308`/`1e38`, `x = 10`) and a
   backward-only `dW` overflow (B-spline far outside its support, `u = 1e300`/`1e30`) — the step is
   attributed ("training step 1"), parameters including `W` equal the reference after the last
   good step, eager `forward`/`backward` raise the same overflow, training continues.
5. Upload/download: exact FP64 round trip, uploaded weights used by the next forward, presence

Python (`residual_python`, CUDA case run, not skipped): forward, input and residual gradients
vs the CPU in FP64 and FP32, download/upload round trip, presence mismatch `ValueError`.

**Test refinements during GREEN** (recorded in `079d981`; no FP64/FP32 check weakened):

- *TF32 weight VJP.* On `wide` the cuBLAS TF32 `dW = U^T*S` missed the C1 TF32 floor
  (`1e-2*max|e|`) by 1.4x: the sums cancel heavily, and TF32 rounds each operand to 2^-11. The
  check now adds `2e-3*sum_b |U||S|` (a GEMM error bound, about four operand roundings) for the
  residual gradient in TF32 only; the CPU-side bound is formed from the layer's actual input and
  upstream.
- *Training trajectory.* The phase 1 network at rate 0.03 escapes the saddle chaotically:
  [chaos.cpp](M3-bench/phase2/chaos.cpp) ([log](M3-bench/phase2/chaos.log)) shows that one ulp in one
  CPU residual weight changes the epoch-250/300 loss by 52%/97%, exactly like the GPU. Before the
  escape the FP64 resident run tracks the CPU to ≤ 6e-16 relative (epochs 0–200). The test
  compares epochs 0/50/100/150/200 (FP64 `1e-12`, FP32/TF32 `1e-3` relative) and requires CPU and
  every precision below half the target variance at epoch 999 (FP64 4.34e-3, FP32 4.35e-3, CPU
  4.56e-3).

**Rejected / not adopted, with numbers:**

- *silu as a (K+1)-th basis term* (zero extra launches): needs an interleaved `[c | w]` parameter
  layout, a row stride in every expansion kernel and C3's recomputation, and does not cover
  rational edges; the brief's block layout was kept.
- *4-output register tiles* in `residual_dot_kernel`: FP64 84 → 98 µs (fewer blocks).
- *cuBLASLt algorithm search*: no gain over `cublasSgemm` once the workspace is 32 MiB.
- *A 32 MiB workspace for the carriers too*: would also speed up the carriers' long-k GEMMs, but
  changes their cuBLAS kernels and results (requirement 1); left as an owner question.
- *Fusing the small-path residual backward into the carriers' `parameter_partial_kernel` /
  `backward_finish_kernel`* (6 launches on the small topology): the graph costs about 1.9 µs per
  kernel there ((167 − 126) µs / 22 kernels), so at most ~11 µs ≈ 6% of the FP32 64-wide step,
  at the price of carrier kernel signatures and λ-ranges spanning the nonlinear block; not done.
- Remaining large-shape cost is the residual GEMMs at cuBLAS efficiency for K = inputs
  (forward 76 µs ≈ 14 TFLOPS, `U*W` 65 µs ≈ 17 TFLOPS per 256-wide layer; carriers 18–22) and
  bandwidth-bound S/silu' writes and `dX` updates.

### Deviations from the brief

1. **Fusions beyond the library-first baseline** (adopted after profiling, as the brief
   allows): S/silu' in `basis_kernel`, the residual sum inside `forward_dot_kernel`, the residual
   GEMM before `bias_kernel`. These touch carrier kernels, through `Residual` template flags whose
   `false` instantiations are the previous code (byte-identical dumps, no frozen regression).
2. **Device summation order** differs from the CPU's "carrier (with bias), then r" for the
   expansion carriers (one partial sum / GEMM accumulation before the bias). Parity is
   tolerance-based, as the brief states.
3. **`silu'` is stored** (one more `capacity*inputs` region per branch layer) instead of
   recomputed: the FP64 exp in the finish kernel cost as much as the dot.
4. **A dedicated 32 MiB cuBLAS workspace** for the branch's GEMMs (arena, conditional), not in
   the brief; measured 104 → 59 µs per 256-wide dW.
5. **New kernels besides "one elementwise kernel":** `residual_dot_kernel` (rational small path),
   `check_kernel`, `residual_finish_kernel`; `parameter_partial_kernel` is reused for dW.
6. **Two test refinements** during GREEN (TF32 GEMM bound, pre-escape trajectory comparison),
   justified above.
7. **README** updated (phase 1 described the branch as CPU only), outside the brief's file list.
8. **Performance-build racecheck not completed** (aborted by the coordinator after about 3 h);
   the parity-build racecheck and every other sanitizer run are clean.

### Open questions for the owner

- **cuBLAS workspace for the carriers.** 4 MiB limits split-K for long-k products: the
  256x256x8192 SGEMM runs in 105 µs at 4 MiB and 54 µs at 32 MiB. The carriers' `dC = U^T*Phi`
  (k = batch) would likely benefit too, but their cuBLAS kernels and results would change
  (golden/f32 dumps). Raise it as a separate, measured item?
- **Small-path backward fusion** (estimated ≤ 6% of the FP32 64-wide enabled step): worth the
  carrier-kernel coupling?
- **Rule-6 note:** GA102 FP64 parity-build kernels execute DMUL+DADD pairs (`--fmad=false`), so
  every FP64 contraction kernel, the branch's included, has twice the FP64-pipe instructions of
  the performance build.

### Documentation corrections (2026-10-10)
