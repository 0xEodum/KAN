# Backlog M5: normalized Hermite functions

Date: 2026-10-14. Branch `cpp-foundation`, base `bd12b0f` (C5 closed, pass 7 complete). Machine:
GB10 (sm_121, unified LPDDR5x), CUDA 13.0, cuBLAS 13.1, GCC 13.3
([port evidence](../port-aarch64.md)). Three Python processes of other users held GPU contexts
(about 15 GB) and were idle (utilization 1%) during the timed runs. Backlog M5 is the review item.
It is not roadmap milestone M5 (quantum carriers), which stays PLANNED.

Finding (BACKLOG M5): the only Hermite option was the physicists' polynomials H_n. They grow like
`sqrt(2^n n!)` and condition poorly at high degree. The task was to offer the normalized Hermite
functions `psi_n(x) = H_n(x) exp(-x²/2) / sqrt(2^n n! sqrt(pi))` as an option.

## Design

**API: a field, not a family.** The physicists' polynomials and the Hermite functions share the
Hermite family and its term count, so the option is a typed field of `HermiteConfig` (R1: each
configuration holds only its family's parameters), not a tenth `BasisConfig` alternative.
- A new variant alternative would have shifted no existing index, because it would be appended.
  But it would have added a family to every visitor, to Python and to the family lists, all
  for one flag.
- `HermiteConfig{6}` still aggregate-initializes to the physicists' polynomials.
- The defaulted `operator==` includes the field. So `upload_parameters` treats a change of
  normalization as a structure change and rejects it with the executor unchanged
  (`upload_rejects_fixed_basis_configuration_changes`, both directions).
- Validation rejects an out-of-range enumerator (`invalid_argument`), so dispatch never sees an
  unknown tag.

**Compile-time instantiation (as C4).** `basis_view(HermiteConfig)` selects `BasisKind::Hermite`
or `BasisKind::HermiteFunction` on the host. `basis_terms_for<Kind>` and `visit_basis_family`
gained one case each. The resident executor therefore instantiates for the new tag:
- `basis_kernel` with and without the residual branch, in FP64 and FP32 (4 kernels);
- the FP32 C3 Φ'-recompute `backward_finish_kernel` (1 kernel).

The new enumerator is appended, so every existing instantiation keeps its mangled name and code:
`sass_cmp.py` gives 173 common kernels, 0 differing and 5 new, in both builds
([sass-identity.txt](M5-bench/sass-identity.txt)). The evaluator is a separate function,
`hermite_function_terms`, so `polynomial_terms` and the physicists' codegen are untouched. The
sparse B-spline path (C5), trainable RBF and rational paths key on their own tags and are
unaffected. No workspace reservation changed: the family has no centers or knots.

**Numerics** (`src/carriers/polynomial/polynomial_formulas.hpp`):

- Recurrence (forward-stable in both the oscillatory and the monotone region):
  `psi_(n+1) = (sqrt(2) x psi_n - sqrt(n) psi_(n-1)) * (1/sqrt(n+1))`, and the derivative
  `psi_n' = sqrt(2n) psi_(n-1) - x psi_n`. `sqrt(n)` is carried from the previous step. The
  reciprocal `1/sqrt(n+1)` does not depend on x, so its division is off the dependent chain.
  Division was 1.10x the physicists' CPU step; the reciprocal brings it to 1.03–1.07x. Both are
  correctly rounded IEEE operations on the CPU and on CUDA, so the term coefficients are bitwise
  equal on every backend.
- The underflow problem: a recurrence seeded with `pi^(-1/4) exp(-x²/2)` returns exact zeros for
  every n once the seed underflows. Examples: FP64 x = 41, n = 840 gives 0 instead of 0.241;
  FP32 x = 14.75, n = 100 gives 0 instead of 0.041. In the subnormal band it loses precision:
  FP64 x = 38.5, n = 741 has a 1.5% error ([naive-recurrence.txt](M5-bench/naive-recurrence.txt)).
- Scaled recurrence: the recurrence runs on `u_n = psi_n · 2^(-B-E) / weight` and starts at
  `u_0 = 2^-B` (B = 512 in FP64, 64 in FP32). When |u_(n+1)| > 1, both live values are scaled
  by `2^-B` with `ldexp` (exact) and E += B. Every output is `u_n · weight`, with
  `weight = pi^(-1/4) exp(-x²/2) 2^(B+E)`. The weight is recomputed (one `exp`) only when E
  changes. For inputs in (-1, 1), as in the benchmarks, no rescale happens. The first rescale
  needs growth `2^B`, from about |x| = 9 in FP32 and 27 in FP64.
- Weight without intermediate underflow:
  - x²/2 is reduced to `j ln2 + r` with `j = nearbyint(x²/(2 ln2))`. The reduction uses
    Cody–Waite with fdlibm's split ln2. The high product is fused, `fma(j, ln2_hi, -x²/2)`;
    the FP32 split alone is exact only for j < 128, |x| ≈ 15 (independent review). The exact
    low part of x·x (`fma(x, x, -x²)`) is also used, so the weight does not inherit the
    `x²·ε` rounding of x·x.
  - The weight is `ldexp(pi^(-1/4) exp(r), B + E - j)`, with the shift clamped at -1100
    (always zero below).
  - Explicit `fma` is a correctly rounded library call, allowed in the parity build, which
    forbids only contraction. On MSVC `std::fma` is correct, and it runs once per input.
- No overflow and no `inf·0`: before a rescale `|u| <= sqrt(2)|x| + 1`. The tail test bounds
  |x|, and the weight is at most `2^B` because the true |ψ| <= 1.
- Exact-zero tail: for `x² >= 8n`, `|H_n(x)| <= (2|x|)^n exp(n²/(4x²))` and `n! >= (n/e)^n`.
  Together they give `ln|psi_n| <= (n/2)(ln(2t) + 1 + 1/(2t) - t) - ln(pi)/4` with `t = x²/n`,
  which is `<= -x²/4` for t >= 8; also `|psi_n'| <= 2|x| exp(-x²/4)`. So for
  `x² >= max(8·size, T)`, with T = 3072 (FP64) or 448 (FP32) chosen so that
  `2|x| exp(-x²/4)` is below half the smallest subnormal, every value and derivative of the row
  rounds to zero. The row is written as exact zeros without evaluation. This also covers
  x = ±1e300 (golden `hermite_overflow`-style inputs) and x² = inf.
- Every output passes the guard (CPU throw, device status), as in the other families. By the
  bounds above no finite input can trigger it.
- Symmetry: ψ_n(−x) = (−1)^n ψ_n(x) holds bitwise (tested).

**Initializer reference measure.** ψ_n are orthonormal under the Lebesgue measure on R, which is
not a probability measure, so the reference measure has to be chosen. The functions keep the
physicists' N(0, 1/2) (density `e^{-x²}/sqrt(pi)`):
- switching the normalization does not change the input distribution that VarianceScaling
  assumes;
- VarianceScaling needs only `m_k = E[phi_k²]`, not orthogonality, because cross terms vanish
  for independent zero-mean coefficients (CONTRACT).

Closed form: `E[psi_n²] = ∫ H_n² e^{-2x²} dx / (2^n n! pi) = 2^(n-1/2) Γ(n+1/2) / (2^n n! pi)
= Γ(n+1/2)/(√2 π n!)`, so `m_0 = 1/sqrt(2 pi)` and `m_n = m_(n-1) (2n-1)/(2n)`. That uses only
basic operations and sqrt, as the M4 portability rule requires. It is checked against the
gamma-function form (Python, 1e-14), against midpoint quadrature under e^{-x²} (C++, 1e-9), and
by the measured output variance of a 32x32 size-24 layer on N(0, 1/2) inputs. The new pinned
digest `e77ab1b759107f4f` was produced with GCC on aarch64; MSVC is not available on this
machine.

## Accuracy

Reference: [hermite_reference.py](M5-bench/hermite_reference.py).
- It evaluates the physicists' recurrence in 700-digit decimal arithmetic at the exact binary x,
  with pi from Machin's formula and exp/sqrt from the decimal module, normalizes afterwards and
  rounds once.
- It shares nothing with the production recurrence.
- Self-test: 700 versus 1400 digits agree exactly on all tabulated cases
  ([reference-selftest.txt](M5-bench/reference-selftest.txt)).
- scipy and mpmath are not installed in the venv, and only the standard library is used.

| Path | Terms, inputs | max \|Δψ\| | max \|Δψ'\|/sqrt(2n+1) | max rel. error, monotone tail (x² > 2n+1+2(2n+1)^{1/3}, \|ψ\| ≥ min normal) |
|---|---|---:|---:|---:|
| CPU FP64 (`evaluate_basis`) | 1024 terms; 266 inputs on [-60, 60] incl. 35–46, 1e10, ±1e300 | 7.6e-14 | 1.9e-14 | 2.9e-13 |
| Resident FP64 (parity / FMA) | 1024 terms; 67 inputs | 6.9e-14 | 1.9e-14 | 2.1e-13 |
| Resident FP32 (parity / FMA) | 128 terms; 235 inputs on [-26, 26] incl. 12–15, 1e5, -3e38 (reference at the FP32-rounded input) | 5.2e-6 / 5.0e-6 | 1.9e-6 | 1.0e-5 / 9.0e-6 (2.5e-5 parity before the review fix of the reduction) |

Logs: [reference-check-parity.txt](M5-bench/reference-check-parity.txt) and
[reference-check-fma.txt](M5-bench/reference-check-fma.txt). The resident values are read
exactly through a 1 → K layer with identity coefficients, and the derivatives through one-hot
upstream rows: one-hot contractions are exact.

Reading the errors:
- The relative error over |ψ| > 1e-8 is 7e-8. It comes from inputs near the zeros of ψ_n, where
  only the absolute error is meaningful.
- The absolute error grows roughly like n·ε, the expected behaviour of a three-term recurrence.
- Tested limits: size 1024 in FP64 and 128 in FP32; `size` is not capped.
- The physicists' FP32 option cannot be compared at size 128: H_127 overflows FP32.

Unit tests (`tests/carriers/hermite_function_test.cpp`) cover:
- closed forms ψ_0…ψ_4 and their derivatives;
- 55 tabulated reference values and derivatives (relative tolerance 2e-12, including subnormal
  ψ_0 and the FP64 underflow window at size 1024);
- orthonormality by the trapezoid rule, which is spectrally accurate for these entire functions:
  48x48 Gram matrix to 1e-13;
- finite-difference derivatives at size 40;
- bounds and finiteness for every input (including ±DBL_MAX and 5e-324, with exact zeros from
  |x| >= 1e10);
- bitwise parity;
- Layer forward and input VJP.

The Python test checks numpy `hermvander` with normalization to 1e-12 and orthonormality by
Gauss–Hermite quadrature (`hermgauss`, 60 nodes, 40 terms, exact for degree < 120) to 1e-12.

## Conditioning demonstration

[conditioning.py](M5-bench/conditioning.py), CPU FP64, deterministic, output in
[conditioning.txt](M5-bench/conditioning.txt).

Design matrix `Φ[b,k] = phi_k(x_b)`, 4096 points. Physicists' condition numbers above about 1e32
are lower bounds: FP64 SVD cannot resolve more.

| size | cond(ΦᵀΦ), N(0,1/2), physicists / function | cond(ΦᵀΦ), wide grid [-L, L], L = sqrt(2K+1)+6, physicists / function | max\|φ\|, physicists / function |
|---:|---|---|---|
| 8 | 3.1e5 / 8.1e2 | 4.5e17 / 1.000 | 5.9e3 / 0.751 |
| 16 | 1.9e19 / 5.9e8 | 3.4e44 / 1.000 | 2.8e9 / 0.751 |
| 32 | ≥ 9e56 / 1.9e28 | ≥ 7e91 / 1.000 | 4.6e22 / 0.751 |
| 48 | ≥ 8e85 / 3.4e32 | ≥ 1e147 / 1.000 | 3.1e37 / 0.751 |

What the table shows (the like-for-like comparison is the N(0, 1/2) column; the wide grid is
the measure under which ψ_n, not H_n, are orthogonal):
- On inputs that cover the support of every ψ_n (|x| ≲ sqrt(2n+1)), the Gram matrix is the
  identity up to scale: perfect conditioning, which the physicists' polynomials cannot reach on
  any domain.
- On inputs concentrated near 0 (N(0, 1/2)), the high-degree functions are nearly dependent,
  still 1e3–1e29 better than the physicists'. That usage note is in CONTRACT: scale inputs with
  an input map for large sizes.
- The RMS of the terms stays within a factor 2.2–3.5 of each other, against 550–2.4e36 for the
  physicists'.

Training: a 2 → 16 → 1 network with tanh between the layers, VarianceScaling, full-batch SGD on
`sin(2x₁)cos(x₂) + 0.3x₁x₂` (512 N(0,1/2) inputs, target variance 0.418), 1500 steps, learning
rates 1e-1 … 1e-6:

| size | physicists: best MSE (rate), diverged rates, initial ‖∇c‖ | function: best MSE (rate), diverged, ‖∇c‖ |
|---:|---|---|
| 8 | 0.129 (1e-6); 1e-1…1e-5 diverge; 5.6e2 | 0.037 (1e-1); none; 2.4 |
| 16 | — ; every rate diverges; 8.7e7 | 0.040 (1e-2); none; 3.6 |
| 32 | — ; every rate diverges; 8.7e20 | 0.042 (1e-2); none; 1.8 |

The physicists' coefficient gradients scale with `sqrt(2^n n!)`. No single learning rate fits
all terms, and from size 16 every tested rate diverges. The Hermite functions train at every
rate with O(1) gradients.

## Observations and open questions

- MSVC was not run (not available on this machine). The pinned initializer digest and
  `std::fma`/`nearbyint`/`ldexp` portability are by construction (IEEE-exact operations) and
  untested there.
- The tested limits are size 1024 (FP64) and 128 (FP32). In FP32 the tail reach `8·size` is
  rounded to float, which loses its conservative margin only beyond about 1.7e7 terms.
- Observation (not M5): the physicists' FP32 basis and Φ'-recompute kernels slow down
  disproportionately at size 32 (896/653 µs against 364/455 µs for the functions), with
  unchanged SASS. A possible follow-up for the physicists' path.
