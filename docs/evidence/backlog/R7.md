# R7: deprecated M1 CUDA API through the resident executor

Backlog item R7 (P2), stage B. Date: 2026-10-05, branch `cpp-foundation`.
Baseline: `2598368` (C2 closed; built as `build-r7base`). Implementation built as `build-r7`.
This changes the public contract of `kan::cuda::forward` / `kan::cuda::backward`
(deprecation, every carrier accepted, resident numerics). `AGENTS.md` rule 5 requires
the change to be recorded, so it is recorded here. The repository owner decided the
approach before the work started: route the M1 API through the resident executor and
mark it `[[deprecated]]`.

## Scheduling: start of pass 4, out of strict priority order

Pass 3 is C2, then C1 (+ C10). C1 and C10 template `src/resident.cu` and `src/detail/` on
`Scalar` and change the CMake `fmad` option. They run concurrently in the main tree. Every
other open item except R7 (R4, R5, R6, M3–M7, C3, C5–C9, C12) touches the same resident
kernels, the directory layout or the formatting of those files, so it would conflict with
that work. R7 touches only the M1 adapter, its tests and documentation. The owner
therefore approved taking R7 (P2) ahead of the open P0/P1 items, as the start of pass 4.
`src/resident.cu`, `src/detail/*` and `include/kan/resident.hpp` are unchanged.

## Change

Before R7, `src/cuda.cu` (239 lines) held its own Chebyshev-only kernels: four or six
`cudaMalloc` buffers and a new stream per call, one thread per output with an O(K) basis
recurrence per term, and a `coefficient_gradient_kernel` that recomputed the recurrence up
to `k` for every coefficient and sample, which is O(K^2 B) per edge. It rejected every other
carrier with `std::invalid_argument`.

After R7, `src/cuda.cu` (60 lines) is a kernel-free adapter:

```cpp
[[deprecated("kan::cuda::forward/backward are deprecated: build a kan::cuda::ResidentNetwork "
             "(kan/resident.hpp) once and reuse it")]]
std::vector<double> forward(const Layer&, std::span<const double> input, std::size_t batch);
// backward: same attribute and unchanged signature
```

Each call:

1. checks for a device (`std::runtime_error`);
2. checks shape products (`std::overflow_error`), shapes and finiteness (`std::invalid_argument`) on the host, before any device allocation;
3. builds a `ResidentNetwork(Network({layer}), batch)` and uploads the input;
4. `forward`: forward, then download the output. `backward`: upload the upstream gradient, forward, backward with `lambda = 0`, then download `layers[0]`;
5. releases the executor on return or on an exception.

### Decisions

- **`available()` is not deprecated.** It is the only device query in the library. The
  resident executor (`src/resident.cu`), every resident test, the benchmarks, the installed
  consumer and the Python `cuda_available()` use it. Deprecating it would warn in
  `src/resident.cu`, which this item must not modify, and would leave resident users without
  a non-deprecated query. A compile probe pins this (see Tests).
- **No executor cache.** A legacy call cannot reuse an executor: the resident API has no
  public parameter upload, and adding one would change the resident header. Caching would
  also break the M1 rule that device memory is owned per invocation. Each call therefore
  pays the executor construction. That cost is the price of the deprecated API, and the
  deprecation message points to the persistent executor.
- **`backward` recomputes the forward pass.** The resident `backward()` requires a current
  forward pass of the same executor. The M1 API never cached activations either.
- **The file and CMake source list are kept.** `src/cuda.cu` stays in `kan_cuda` (now without
  device code; it also defines `available()`). This keeps the `add_library` line that the C1
  work edits unchanged and eases the merge.
- **Python.** The bindings never exposed `kan::cuda::forward/backward`; they include
  `kan/cuda.hpp` only for `cuda_available()`, which is not deprecated. There is nothing to
  deprecate in Python and no `DeprecationWarning` to emit. `python/bindings.cpp` is unchanged.

### Contract changes

| Aspect | M1 (before) | R7 (after) |
|---|---|---|
| Declaration | plain | `[[deprecated]]` with a message pointing to `ResidentNetwork`; signatures unchanged |
| Carriers | Chebyshev only; others raise `invalid_argument` | every resident carrier: all nine basis families, `TrainableRbfEdges` (nonlinear VJPs in `LayerGradients::nonlinear`), `RationalEdges` under all three denominator policies |
| Rational pole | n/a | `std::domain_error`, as on the CPU and the resident path |
| Numerics | own kernels, `--fmad=false`, sequential sums | resident executor: cuBLAS/small-kernel contractions; CPU/GPU agreement within `|a-e| <= 1e-12|e| + 1e-13 max|e|` per entry |
| Nonfinite results | `overflow_error`; intermediate overflow reported (unfused) | `overflow_error` for every nonfinite result tensor; an intermediate overflow cancelled inside a fused contraction is not reported if the result is finite (the C2 resident contract) |
| Errors before allocation | runtime / invalid_argument / overflow | unchanged (host checks run before the executor is built) |
| Device memory | owned per call | owned per call (one executor) |
| Empty batch | empty output, zero parameter gradients | unchanged; nonlinear VJPs correctly shaped and zero |
| `available()` | supported | supported, not deprecated |

The owner accepted in pass 3 (C2) that CPU and GPU results are not bit-identical. The
tolerance above is the C2 per-entry comparison of the resident suites, which the M1 API now
inherits. The old suite used `2e-11 (1 + |e|)`.

## Tests

`tests/cuda_test.cpp`, rewritten in the RED commit `161f496`. It failed 4/11 against the
unchanged M1 code, and the deprecation probe failed too ([R7-red.log](R7-red.log)):

- kept from M1: Chebyshev parity across shapes, endpoint derivatives and unclipped
  `|x| > 1`, empty batch, invalid shapes and nonfinite data, shape overflow before
  allocation, nonfinite computed results (including the degree-538 derivative overflow
  in forward), the no-device mode (`--expect-no-device`, checked with
  `CUDA_VISIBLE_DEVICES=-1`);
- **new** `cuda_legacy_api_supports_every_resident_carrier`: 12 layers (Chebyshev,
  Legendre, Jacobi(0.5, -0.3), Hermite, Fourier, Gaussian RBF, cubic B-spline, Mexican
  hat, trainable RBF with moved centers/log widths, rational Guarded/Absolute/Smooth) at
  3->2 for batches 1 and 37, and at 5->4 for batch 129. Forward, input, coefficient, bias and
  nonlinear VJPs are compared against the CPU;
- **new** `cuda_legacy_empty_batch_shapes_every_carrier` (gradient shapes equal the CPU's);
- **new** `cuda_legacy_reports_unsafe_rational_denominator` (`domain_error` in forward and backward);
- extended: concurrent calls now also run every carrier on a third thread;
- **new** `cuda_legacy_calls_release_device_storage`: 3 x 40 forward + backward + throwing
  calls on a 64->64 layer, about 8 MiB of executor per call. `cudaMemGetInfo` free memory
  must not drop by 64 MiB or more; a leak of the executors would lose several hundred MiB per cycle. Up to three attempts tolerate
  other processes on the shared GPU;
- **new** CTest compile probes `cuda_deprecation_available` / `cuda_deprecation_legacy`
  ([probe](../../../tests/cuda_deprecation_probe.cpp), built `EXCLUDE_FROM_ALL` with `/we4996`
  or `-Werror=deprecated-declarations`). The first compiles `available()` plus a
  `ResidentNetwork` and must succeed. The second must fail with the deprecation diagnostic
  naming `ResidentNetwork`. GCC 15 produces the matching diagnostic too (checked with
  `-fsyntax-only`; GCC builds are CPU-only and do not register the probes). Like the
  `package_*` tests, the probes need the compiler environment at test time
  (`scripts\build.ps1 -Test` provides it).

Removed:

- `cuda_rejects_unsupported_families`: superseded by the contract change.
- `cuda_preserves_unfused_intermediate_overflow_contract`: this guarantee belonged to the
  `--fmad=false` M1 kernels. The resident contract (C2) explicitly does not report an
  intermediate overflow that a fused contraction cancels, and C10 enables FMA in the
  performance build.

## Benchmarks and profiling

The timings are **diagnostic**. They were taken on the shared RTX 3090 under WDDM while the
concurrent C1 session kept it busy (68–98% utilization, up to 13.5 GB in use). They are not a
frozen-protocol measurement.

**Legacy call wall time** ([legacy_timing.cpp](R7-bench/legacy_timing.cpp); median of 21 / 5
calls after 2 warmups; two alternating rounds: base, base, R7, R7 CSVs in [R7-bench/](R7-bench/)):

| Case (Chebyshev K=8) | Call | Base (ms) | R7 (ms) | R7/base |
|---|---|---:|---:|---:|
| 16->8, batch 32 | forward | 0.46 / 0.50 | 1.07 / 1.10 | 2.2x slower |
| 16->8, batch 32 | backward | 0.64 / 0.66 | 1.20 / 1.26 | 1.9x slower |
| 128->128, batch 4096 | forward | 28.5 / 27.7 | 14.3 / 15.2 | 1.9x faster |
| 128->128, batch 4096 | backward | 177.6 / 175.6 | 24.0 / 23.9 | 7.4x faster |

**Frozen m2 `m1_host_full` rows** (`m2_benchmark --backend legacy`, default 2 warmups / 7
repeats, full step over 2–3 layers; base, R7, R7, base; ms):

| Case | Base | R7 |
|---|---:|---:|
| 0: 16x24x8, batch 32 | 5.7 / 7.5 | 16.7 / 20.8 |
| 1: 16x24x8, batch 1024 | 23.5 / 34.5 | 16.7 / 17.6 |
| 2: 64x64x32x16, batch 32 | 13.6 / 18.2 | 27.3 / 41.2 |
| 3: 64x64x32x16, batch 1024 | 54.8 / 90.2 | 33.1 / 39.9 |

**Nsight Systems (AGENTS.md rule 6)**, `--trace=cuda` on the timing tool, case by case
([nsys-api.csv](R7-bench/nsys-api.csv), [nsys-kernels.csv](R7-bench/nsys-kernels.csv),
[profile_legacy.ps1](R7-bench/profile_legacy.ps1)):

- **`cudaMalloc` per call is unchanged: 5 on average** (230 for 46 calls in the small case,
  70 for 14 in the large case, in both builds). The baseline allocated 4 buffers in forward
  and 6 in backward. R7 allocates what one resident executor needs: the arena and the
  status word (`workspace_allocations() == 2`, as C2 recorded) plus 3 allocations inside
  `cublasCreate`. The adapter allocates nothing itself and makes no allocation during
  execution.
- **Small case: GPU time fell, host-side construction now dominates.** Per call the baseline
  kernels took about 340 us (`coefficient_gradient_kernel` 171 us, `forward_kernel` 108 us,
  `input_gradient_kernel` 59 us). The resident kernels take about 25 us
  (`basis_kernel` 6.5 us, small `d884gemm` 8 us, `parameter_partial_kernel` 7 us,
  `forward_dot_kernel` 3 us). The extra wall time is the construction and release of the
  executor (API medians per call): 5 `cudaMalloc` at 28 us against 1.7 us (the arena is
  several MiB, including the 4 MiB cuBLAS workspace), 6 `cudaFree` at 38 us against 5 at
  1.5 us, 6 stream synchronizations against 2, 7 small copies at 15 us, and the handle's
  18 events. The resident API avoids these only if the executor is reused, which is what
  the deprecation message recommends.
- **Large case: the O(K^2 B) kernel is gone.** Baseline backward is 76% `coefficient_gradient_kernel`
  (147 ms per launch). R7 backward is three cuBLAS DGEMMs of 2.2–2.8 ms plus the basis kernel
  (0.5 ms). The remaining time is the pageable copies of the 4 MiB input/output and gradient
  tensors. In both builds the `cudaMemcpyAsync` totals also include waiting for the kernels.

## Open question for the owner

- Should `available()` later move to (or also be declared in) `kan/resident.hpp`, so that
  resident users need not include the header of a deprecated API? This was deferred because
  the resident header is being changed by C1.
- The deprecated call is now about 2x slower than M1 for tiny layers and much faster for
  large ones. If the per-call cost of small legacy calls matters, a resident parameter-upload
  entry point would allow a per-thread executor cache. That would be a resident API change,
  so it was not done here.
