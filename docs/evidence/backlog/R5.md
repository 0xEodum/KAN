# R5: tests and benchmarks named by feature

Backlog item R5 (P1), stage B, pass 7 (R4 → R5 → C5). Date: 2026-10-13, branch
`cpp-foundation`, base `72e071c` (R4 closed). Machine and commands as in
[port-aarch64.md](../port-aarch64.md): Linux aarch64, GB10 (sm_121), CUDA 13.0, GCC 13.3,
Release builds `build-cpu` (CPU-only + Python), `build-cuda` (parity, Python, benchmarks)
and `build-cuda-fma` (performance build, Python, benchmarks).

R5 is a rename and regrouping of `tests/` and `benchmarks/` (with `git mv`). No library
source changed, so `libkan.a` and `libkan_cuda.a` were not rebuilt by the change; test
bodies changed only in case-name prefixes and two Python class names. No contract change.

## Design

**Names.** The milestone-named suites were named after roadmap milestones M3 (localized
families: B-spline, Mexican hat, trainable RBF) and M4 (rational edges). Their feature
names follow the R4 carrier groups:

| Old CTest / file | New CTest | New file |
|---|---|---|
| `m3_basis` | `local_basis` | `tests/carriers/local/local_basis_test.cpp` |
| `m3_layer` | `local_layer` | `tests/carriers/local/local_layer_test.cpp` |
| `m3_resident` | `local_resident` | `tests/backends/cuda/local_resident_test.cpp` |
| `m3_python` | `local_python` | `tests/python/local_python_test.py` |
| `m3_large_basis_test` (manual, not in CTest) | `local_large_basis_test` | `tests/backends/cuda/local_large_basis_test.cpp` |
| `m4_rational` | `rational` | `tests/carriers/rational/rational_test.cpp` |
| `m4_layer` | `rational_layer` | `tests/carriers/rational/rational_layer_test.cpp` |
| `m4_allocation` | `rational_allocation` | `tests/carriers/rational/rational_allocation_test.cpp` |
| `m4_resident` | `rational_resident` | `tests/backends/cuda/rational_resident_test.cpp` |
| `m4_python` | `rational_python` | `tests/python/rational_python_test.py` |
| `m2_benchmark` | `basis_benchmark` | `benchmarks/basis_benchmark.cpp` |
| `m3_benchmark` | `local_benchmark` | `benchmarks/local_benchmark.cpp` |
| `m4_benchmark` | `rational_benchmark` | `benchmarks/rational_benchmark.cpp` |

All other suites already had feature names (`layer`, `basis`, `resident_training`,
`rational_policy`, ...). They keep their names and only move into a directory. `cuda`
(the deprecated legacy API) and `python` (general bindings) were left as they are. They
are not milestone names, and renaming them would only cost history.
Inside the renamed files, the case-name prefixes `m3_resident_` and `m4_resident_` became
`local_resident_` and `rational_resident_`. The Python classes `M3` and `M4` became
`Local` and `Rational`, and two installed-consumer messages dropped "M3"/"M4". Comments
that cite backlog items ("Backlog M3") are references, not names, and were kept.

**Benchmark names.** The frozen suites are named after their case sets:
- `basis_benchmark` (old m2): the fixed `BasisEdges` families Chebyshev, Legendre,
  Jacobi, Hermite, Fourier and Gaussian RBF. Gaussian RBF is a local family, so "global"
  would be false.
- `local_benchmark` (old m3): B-spline, Mexican hat and trainable RBF.
- `rational_benchmark` (old m4): rational 1/1, 3/2 and 6/4.

Cases, case ids, family strings, CLI options (`--backend all|cpu|legacy|resident`,
`--case`, `--warmups`, `--repeats`) and CSV columns (including the rational suite's
`degrees`) are unchanged.

**Layout: subdirectories mirroring `src/`.** There were 44 test files in one flat
directory, and the R4 layout gives a natural grouping. One axis per mechanism:
the directory carries the feature, and the CTest label carries the execution requirement.

| Directory | Suites |
|---|---|
| `tests/core/` | `layer`, `network`, `input_map`, `residual`, `residual_formula`, `residual_training` |
| `tests/carriers/` | `basis`, `basis_config`, `carrier` |
| `tests/carriers/local/` | `local_basis`, `local_layer` |
| `tests/carriers/rational/` | `rational`, `rational_layer`, `rational_allocation`, `rational_policy` |
| `tests/init/` | `initializer`, `initializer_training` |
| `tests/backends/cuda/` | every suite that needs a GPU: `cuda` and the `cuda_deprecation_*` probe source, `resident*`, `local_resident`, `rational_resident`, `rational_policy_resident`, `rational_resident_execution`, `input_map_resident`, `residual_resident`, `initializer_resident`, manual `local_large_basis_test` |
| `tests/python/` | all nine Python suites |
| unchanged | `tests/support/`, `tests/consumer/`, `tests/package_test.cmake` |

The `*_resident` suites belong to `backends/cuda/`, not to the carrier directories. The
same is true of the sources: `resident.cu` holds every carrier's kernels under
`src/backends/cuda/`. This also lets a CPU-only reader skip one directory. There is no
`carriers/polynomial/` or `carriers/trigonometric/` test directory, because `basis` and
`basis_config` cover all families through one API and git does not track empty
directories. `tests/support/` stays put, because the
includes are `"support/..."` with `tests/` on the include path (also used by
`port-aarch64/tf32/tf32_diag.cpp`). Every target is still declared in the root
`CMakeLists.txt` (no `add_subdirectory`), so executables stay in the build root, which
`scripts/sanitizers.sh` (`$build/$test`) and `scripts/bench_baseline.sh` rely on.

**CMake.** The 20 copies of the `add_executable` / `add_test` block were replaced by
`kan_add_test(<dir> <name> <labels> <timeout> <libraries>...)`, and the nine Python
blocks by `kan_add_python_test(<name> <labels>)`. A file `<name>_test.{cpp,py}` is
always CTest `<name>`. Each test keeps its old properties: timeouts (60 CPU, 120/180/600
CUDA, 900 for the two training demonstrations), link libraries (`Threads` for `cuda` and
`resident`, `CUDA::cudart` for `cuda` and `resident_fused_expansion`), the `src/` include
of `residual_formula_test`, and the deprecation probes' `RESOURCE_LOCK` and pass
regex.

**Labels.** The existing labels `cpu`, `cuda`, `python`, `integration` and `build` are
unchanged per test, and the label summaries in the logs are identical before and after:
- CPU build: cpu 20, integration 12, python 9.
- CUDA builds: build 3, cpu 20, cuda 18, integration 12, python 9.

One feature-group label was added per test: `core`, `carriers`, `local`, `rational`,
`init`, or `resident` (the carrier-independent executor and binding suites). For example,
`ctest -L rational` runs the 5 CPU/Python rational suites, plus 3 CUDA ones in a CUDA
build. None of the group names is a substring of another label, so `-L cpu` / `-L cuda`
select exactly the sets they selected before.

**Frozen benchmark labels: renamed, with a mapping that the tooling applies.** The
backend column carried milestone names. It now reads:
- `m1_host_full` → `legacy_full`
- `m2_resident_full`, `m3_resident_full`, `m4_resident_full` → `resident_full`
- `m2_transfer_full`, `m3_transfer_full`, `m4_transfer_full` → `transfer_full`
- `cpu_full` is unchanged.

The suite moves to the file name (`frozen-basis.csv`, ABBA `basis-<tag>-<n>.csv`).
Recorded CSVs, including the aarch64 baselines, are not rewritten. Instead,
[bench_labels.py](bench_labels.py) holds the old → new table (suites m2/m3/m4 →
basis/local/rational, plus the backend labels above), and
[compare_bench.py](compare_bench.py) normalizes both sides through it. Either side may
use either naming. Changes to `compare_bench.py`:
- `--frozen <before-dir> <after-dir>` compares two `scripts/bench_baseline.sh` outputs
  (`frozen-<suite>.csv`).
- Keys present on one side only are listed and make the exit status non-zero, so an
  incomplete mapping cannot pass silently.
- Only suite files are read. The old glob `*-<tag>-*.csv` also picked up
  `large-build-b-c1-*.csv` in C1-bench and `large-c2-*.csv` in C2-bench, which crashed it
  there.
- Checksum mismatches are listed but do not fail the run (expected across builds that
  change summation order). Wrong argument counts print the usage.

### Frozen benchmarks against the recorded aarch64 baseline

The renamed executables ran in the parity build (the build the port baseline used) with
the flags of `bench_baseline.sh` (`--warmups 2 --repeats 7`), giving
[frozen-{basis,local,rational}.csv](R5-bench/frozen/). The comparison is
`compare_bench.py --frozen docs/evidence/port-aarch64/bench docs/evidence/backlog/R5-bench/frozen`,
with the baseline in old labels and the new run in new labels
([output](R5-bench/frozen/compare-port.txt), exit 0):

| suite | backend | cases | geomean after/before | min | max |
|---|---|---:|---:|---:|---:|
| basis | cpu_full | 24 | 1.006 | 0.995 | 1.028 |
| basis | legacy_full | 4 | 1.092 | 1.013 | 1.342 |
| basis | resident_full | 24 | 0.970 | 0.938 | 1.065 |
| basis | transfer_full | 24 | 0.967 | 0.936 | 0.995 |
| local | cpu_full | 12 | 1.001 | 0.995 | 1.006 |
| local | resident_full | 12 | 0.959 | 0.907 | 1.029 |
| local | transfer_full | 12 | 0.972 | 0.940 | 1.000 |
| rational | cpu_full | 12 | 1.006 | 1.003 | 1.009 |
| rational | resident_full | 12 | 0.951 | 0.926 | 0.967 |
| rational | transfer_full | 12 | 0.958 | 0.951 | 0.978 |

All 148 baseline keys matched (no key on one side only). There were 0 checksum
mismatches: outputs, gradients and parameters are identical to the port baseline. The
`legacy_full` maximum came from one sample window of case 3 (27.7 ms against 20.7 ms).
Two reruns of `--backend legacy` gave 6.66/9.32/11.02/21.06 and 6.80/9.39/11.07/21.31 ms,
against the baseline's 6.68/9.12/10.95/20.66 ms ([rerun](R5-bench/frozen/legacy-rerun.txt)).
That is within 3%, the per-call executor construction is noise-sensitive, and the code is
unchanged.

### Historical comparisons still work

`compare_bench.py` was run on recorded ABBA directories before and after the change
([output](R5-bench/compare-historical.txt)):
- M2-bench, R3-bench and R8-R9-bench give the same rows (cases, ratios, checksum counts)
  with labels mapped to the new names.
- C1-bench and C2-bench crashed before (non-suite files matched the glob) and now
  produce their comparisons. C2's 66 checksum mismatches are its recorded cuBLAS
  summation-order change.

## Paths updated

- `CMakeLists.txt` (test and benchmark sections, helpers, labels).
- `scripts/sanitizers.sh` (memcheck list), `scripts/bench_baseline.sh` (suite loop,
  output names), `scripts/benchmark-m2.ps1` (default `basis_benchmark.exe`).
  `build.ps1` and `build.sh` name no tests. CI runs whole CTest suites.

  `docs/CONTRACT.md` (two test paths), `docs/BACKLOG.md` (quick context, R5 row,
  journal).
- `docs/evidence/backlog/compare_bench.py` and the new `bench_labels.py`.

Not rewritten (historical evidence describing earlier states):
- evidence documents and recorded CSVs with `m2/m3/m4_benchmark`, `tests/m*_test.*` or
  the old labels;
- `docs/evidence/m4/summarize_matched.py` (it processes only its own recorded
  `balanced-*.csv`, which keep the old labels);
- `docs/evidence/backlog/rational_policy_profile.cpp` (a comment naming the m4 fixture);

To re-run them against the current tree, use the table above:
`m2/m3/m4_benchmark` → `basis/local/rational_benchmark`, `tests/<name>_test.*` →
`tests/<dir>/<new name>_test.*`.
