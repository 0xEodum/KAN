# R3 (+C4): single host/device source for carrier formulas

Backlog items R3 (P0) and C4 (P1), stage B. Date: 2026-10-01, branch `cpp-foundation`.

## Change

Formulas were duplicated between the CPU backend and the resident CUDA kernels:
`src/basis.cpp` ↔ `src/resident.cu` (Jacobi/Legendre/Chebyshev/Hermite recurrences,
Fourier, log-space Gaussian and Mexican hat, Cox–de Boor) and `src/rational.cpp` ↔
`src/resident.cu` (Horner, pole guard, log-space input derivative, parameter VJPs).

They now live once, as `KAN_HOST_DEVICE` header templates:

- `src/detail/host_device.hpp`:
  - `KAN_HOST_DEVICE` and `KAN_FORCE_INLINE`;
  - a `math::` facade over `<cmath>` (host) and CUDA's global overloads (device);
  - exact constants `min_normal` and `ln2`.
- `src/detail/basis_formulas.hpp`:
  - per-family `*_terms` evaluators over a non-owning `BasisView`;
  - `basis_terms_for<Kind>` (family fixed at compile time);
  - a host-only runtime dispatcher, `visit_basis_family` / `basis_terms`.
- `src/detail/rational_formulas.hpp`: `rational_horner`, `rational_pole`,
  `rational_edge`, `rational_numerator_vjp` and `rational_denominator_vjp`.

Each formula takes a `Guard`, a callable that checks finiteness:

- CPU guards throw `std::overflow_error`; the messages are unchanged.
- The device `StatusGuard` sets status bit 1 and continues, as `report` did before.
- `rational_parameter_kernel` uses the identity guard `CheckedEarlier`. Its inputs
  are bit-identical to values that `rational_forward_kernel` already checked, and
  backward requires a successful forward.

The pole policy stays at the call site: the CPU throws `std::domain_error` and the
device sets bit 2.

The CPU B-spline now uses the device algorithm: a binary span search and fixed
`degree+2` scratch over the active span. It replaces a full-length Cox–de Boor
table that allocated vectors on every call. Both algorithms do the same
floating-point operations on every nonzero term.

**C4.** `basis_kernel` is a template over `BasisKind`, and the host launches the
instantiation for each layer's family. Before, one kernel carried the code of all
eight families, 66 registers and a 336-byte stack (spline scratch). Now:

| Family | Chebyshev | Legendre | Jacobi | Hermite | Fourier | Gaussian | B-spline | Mexican hat |
|---|---|---|---|---|---|---|---|---|
| Registers | 36 | 50 | 62 | 40 | 40 | 44 | 60 | 42 |
| Stack, bytes | 0 | 0 | 0 | 0 | 40 | 0 | 288 | 0 |

`src/cuda.cu` (the legacy M1 Chebyshev API) is not touched; it belongs to R7.
The host `kan` target gets `-ffp-contract=off` for GCC/Clang: CPU results must not
contract into FMA, consistent with the `--fmad=false` CUDA build.

## One semantic unification

Before the change, the GPU checked a rational parameter VJP only for its final
value, while the CPU also checked the intermediates `z^k/Q` and `-r·z^k/Q`. Both
backends now check the intermediates in forward.

The two can disagree only when the denominator VJP takes the log-space path
(`r` subnormal) while `-r·z^k/Q` overflows. In that case the CPU already threw
`overflow_error` and the GPU used to return a finite gradient. The GPU now reports
it as well.

## Equivalence

Baseline: `build-b-base` at `ca4cea8`. After: `build-b-r3`. Both are built with
`scripts/build.ps1 -Cuda -AllowUnsupportedCudaCompiler -Python -Benchmarks -Test`
(MSVC 19.50, CUDA 13.1, RTX 3090, sm_86). The CPU-only GCC 15 (MSYS2 ucrt64)
build was also checked after the change.

| Check | Baseline | After |
|---|---|---|
| CTest, MSVC + CUDA | 19/19 | 19/19 |
| CTest, GCC CPU-only | — | 11/11 |
| Golden dump SHA-256 | `64F22EB8…8CD60A3B` | `64F22EB8…8CD60A3B` (byte-identical) |
| Frozen benchmark checksums (m2/m3/m4, all backends) | — | 0 mismatches |

The golden harness ([golden/golden.cpp](golden/golden.cpp), built by
[golden/build_golden.cmd](golden/build_golden.cmd)) prints the following as exact
hex doubles, including every guard exception (type and message):

- every CPU basis family over 25 inputs: Jacobi endpoints, the near-boundary and
  overflowing parameters, B-splines of degree 0/1/3/16, repeated interior knots
  and a huge domain, Gaussian/Mexican-hat tails;
- six rational configurations (poles, subnormal paths, degree 16/16);
- five resident CUDA networks, three forward/backward/SGD steps each, with all
  outputs, gradients and trained parameters, plus nonfinite and pole status
  propagation.

The dump is deterministic between runs: 176 090 bytes, with 52 basis overflows,
12 rational overflows, 2 rational poles, 1 resident overflow and 1 resident pole.
It stayed byte-identical after each change below, including the two literal
constants (they equal the previously computed doubles bit for bit).

## Profiling (AGENTS.md rule 6)

The first working version was measured before it was accepted. Three regressions
were found and removed:

1. **`rational_parameter_kernel` +17.7%.** nsys on m4 case 11 measured 2.92 → 3.44 ms.
   - Cause: guards inside the per-sample reduction loop.
   - Fix: the identity guard `CheckedEarlier` (see above). Afterwards ncu shows an
     identical instruction count (201 944 256) and time (7.28 ms) to the baseline.
2. **Trainable RBF `basis_kernel` +22%, Mexican hat +3%.**
   - ncu showed +23% FP64-pipe and +33% XU instructions. Behind the inline
     `math::` wrappers, nvcc no longer folded `log(2.0)` or the wavelet
     normalization `log(2/√3) − ¼·log π` into constants.
   - Fix: exact literals `math::ln2` (`0x3FE62E42FEFA39EF`) and `-0x1.2383e809a67e3p-3`.
3. **CPU rational [1/1] +33%.** A micro benchmark showed 64×64 edges × 256 samples
   at 28.9 → 38.4 ms forward.
   - Cause: MSVC did not inline the nested formula templates, plus a recomputed
     `z^k/Q`, `P/Q` per power.
   - Fix: `KAN_FORCE_INLINE` on the rational formulas, and VJPs that take the
     shared `divided = z^k/Q` and `r = P/Q`.
   - Result: [1/1] 28.7 ms (= baseline), [3/2] 38.7 ms (−12%), [6/4] 58.9 ms (−15%).

## Review

An independent `cpp-reviewer` pass found no CRITICAL or HIGH issues. Its findings
and how they were handled:

- **Fixed:** GCC/Clang include path inside `src/detail`.
- **Fixed:** host FMA contraction on non-MSVC compilers.
- **Fixed:** a silent no-op on an unvalidated kind; it now throws `logic_error`,
  with a `static_assert` on the polynomial fallback.
- **Fixed:** the `CheckedEarlier` comment now states the invariant it relies on.
- **Accepted and recorded above:** the stricter device check in a contrived tail
  case.
