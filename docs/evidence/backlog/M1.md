# M1: explicit typed input maps as a network layer kind

Backlog item M1 (P0), stage B. Date: 2026-10-02. Base: `5dc6819` (R2 closed).
This is a public API and contract change, recorded here as `AGENTS.md` requires.
(Not to be confused with milestone M1, [../M1.md](../M1.md).)

## Problem

The contract forbids implicit normalization, but there was no explicit tool for it.
Polynomial edges grow like `(2|x|)^n` for `|x| >> 1`, so gradients explode. Localized
bases (B-spline, RBF, Mexican hat) are zero, with zero gradient, outside `[t_p, t_K]`
or their support, so those edges are dead. The demonstration below shows both
failures on the CPU, on data `x` in `[100, 500]` with a quadratic target.

## Change

Input maps are a new **network layer kind**, not a flag on `Layer` (R2's open point),
in `include/kan/input_map.hpp` and `src/input_map.cpp`:

```cpp
struct AffineMap    { std::vector<double> scale, shift; };              // fixed
struct TanhMap      { double scale = 1.0; };                            // fixed
struct LayerNormMap { double epsilon = 1e-5; std::vector<double> gain, bias; }; // gain/bias trainable
using InputMapKind = std::variant<AffineMap, TanhMap, LayerNormMap>;
struct InputMapGradients { std::vector<double> input, gain, bias; };
class InputMap { InputMap(std::size_t features, InputMapKind); forward; backward; sgd; set_map; ... };
AffineMap affine_from_range(samples, batch, features, lower = -1, upper = 1);
AffineMap affine_from_moments(samples, batch, features);
```

`Network` (`include/kan/network.hpp`) becomes a sequence of heterogeneous layer kinds:

```cpp
using NetworkLayer          = std::variant<Layer, InputMap>;
using NetworkLayerGradients = std::variant<LayerGradients, InputMapGradients>;
struct NetworkGradients { std::vector<double> input; std::vector<NetworkLayerGradients> layers; };
```

### Decisions

- **A layer kind, as a `std::variant`.** This matches R1/R2: the kinds are values with
  `operator==`, dispatch happens once per layer and call (`std::visit` in `Network`, one
  per map in `InputMap`), and the loops are compiled per kind with no per-element
  dispatch. A map is not an edge carrier: it has shape `I -> I` with no per-edge
  coefficients, and it can sit in front of any carrier (polynomial, localized,
  trainable RBF, rational) without each carrier repeating it.
- **Affine is fixed.** Its job is to put inputs into a basis domain. A trainable scale
  could move them out again, which is the dead-edge failure M1 removes, and the first
  KAN layer already learns the response inside the domain. Two data-driven
  constructors cover the common cases:
  - `affine_from_range` maps each feature's sample min/max onto `[lower, upper]`, for
    example a spline domain or `[-1, 1]`;
  - `affine_from_moments` standardizes.
  Zero scales are rejected, because a zero scale would make a feature silently
  constant.
- **Tanh has a fixed positive pre-scale.** For per-feature pre-scales, put an affine map
  in front of it.
- **LayerNorm uses a population variance (two passes) and a fixed epsilon.** Gain and
  bias are optional and either both present or both absent; when present they are
  trainable, as in standard LayerNorm. With one feature, `xhat = 0` and the output
  is the bias.
- **Index semantics.** Every Network index (`insert_knot`, `adapt_grid`, `layers()`,
  `NetworkGradients::layers`) is a position in the full sequence, maps included.
  Family operations at an input map raise `invalid_argument("layer index does not
  refer to a KAN layer")`. Network SGD rejects a gradient alternative that does not
  match its position.
- **Regularization.** The coefficient L2 keeps its definition and acts on KAN layer
  coefficients only. A map contributes zero value, zero gain/bias gradients and an
  empty input gradient, consistent with the unpenalized RBF centers/widths and
  rational denominators. The resident `backward(lambda)` does the same.
- **Compatibility.** `Network(std::vector<Layer>)` stays valid. It is a constrained
  template, so `Network({a, b})` with braces still selects the `NetworkLayer`
  constructor unambiguously. `Network::inputs()` and `outputs()` are new.
- **Moved-from maps.** The move operations zero `features_`. Every operation,
  including network construction, then raises `invalid_argument`, as for `Layer`.
- **Single formula source (R3).** The formulas live in
  `src/detail/input_map_formulas.hpp` as `KAN_HOST_DEVICE` functions:
  - `affine_value`, `tanh_value`, `tanh_derivative`;
  - `layer_norm_mean`, `layer_norm_rstd`, `layer_norm_normalized`;
  - `layer_norm_input_vjp`.
  The row reductions are sequential on the CPU and use group shuffles on the device,
  so parity is tolerance-based, as the contract already states.
- **Resident executor.** The `Plan` variant gains `AffinePlan`, `TanhPlan` and
  `LayerNormPlan`.
  - Fixed map parameters (affine scale/shift) live in the workspace.
  - Trainable gain/bias live at `[gain | bias]` in the parameter, gradient and
    candidate regions, so the existing candidate kernel and the pointer-swap commit
    give them network-wide atomic SGD unchanged.
  - `with_stage` pairs each plan with its `Layer` carrier or `InputMap` kind.
  - Gradient and parameter downloads are per-plan overloads.
  - For networks without maps, the plan construction, reservation order, arena
    layout and launch sequence are unchanged.
- **Python mirrors the API.** It adds `kan.AffineMap`, `kan.TanhMap`, `kan.LayerNormMap`,
  `kan.InputMap`, `kan.InputMapGradients`, `kan.affine_from_range` and
  `kan.affine_from_moments`. `kan.Network` takes and returns mixed lists, and
  `NetworkGradients.layers` mixes gradient classes. pybind11's `std::variant` caster
  needs a default-constructible variant and `Layer` has none, so the network-layer
  lists are converted explicitly (`network_layers`, `py::list` results).

## Mathematics of the VJPs

Notation: `u = dL/dy`; sums over the batch `b` are written explicitly.

- **Affine:** `y = a*x + c`, so `dx = a*u`. There are no trainable parameters.
- **Tanh:** `y = tanh(s*x)`, so `dx = u*s*(1 - y^2)`, evaluated as `u*s*(1-y)*(1+y)`.
  - The factored form avoids the cancellation in `1 - y*y`.
  - Its relative error is about `ulp(1)/(1-|y|)`, so it degrades only where the
    derivative is already below about `1e-8*s`.
  - A saturated `y = ±1` gives exactly 0, never a nonfinite value.
  - The first version used `s/cosh(s*x)^2`. Profiling replaced it (see below):
    three FP64 operations from the saved output instead of FP64 `cosh` and a
    division.
- **LayerNorm**, per sample over `n` features:
  - Forward: `mean = (Σx)/n`, `var = (Σ(x-mean)^2)/n`, `r = 1/sqrt(var+eps)`,
    `xhat = (x-mean)*r`, `y = g*xhat + β`, or `y = xhat` without gain and bias.
  - Derivative of `xhat`: `∂xhat_i/∂x_j = r*(δ_ij - 1/n - xhat_i*xhat_j/n)`.
  - Input VJP: with `w = u*g` (or `u`),
    `dx_j = Σ_i w_i ∂xhat_i/∂x_j = r*((w_j - mean(w)) - xhat_j*mean(w*xhat))`.
  - Parameter VJPs: `dg_i = Σ_b u_bi*xhat_bi` and `dβ_i = Σ_b u_bi`.
  - Means are `sum * (1/n)` with the reciprocal computed once, on both backends.
  - Nonfinite row moments raise `overflow_error`. An overflowing variance would
    otherwise give `r = 0` and a silently finite output.

Each VJP is checked against central differences:

- in `tests/input_map_test.cpp`: input, gain and bias, with and without affine;
- at network level, maps in front of polynomial, B-spline, trainable-RBF,
  Mexican-hat and rational layers, every parameter of every position.

## Migration

| Before | After |
|---|---|
| `network.layers()[i].coefficients()` | `std::get<kan::Layer>(network.layers()[i]).coefficients()` |
| `std::vector<kan::Layer> v(net.layers().begin(), net.layers().end())` | iterate `net.layers()` and `std::get<kan::Layer>` (or keep a `std::vector<kan::NetworkLayer>`) |
| `gradients.layers[i].coefficients` | `std::get<kan::LayerGradients>(gradients.layers[i]).coefficients` |
| `network.layers().front().inputs()` | `network.inputs()` |
| `kan::Network({layer_a, layer_b})`, `kan::Network(std::vector<kan::Layer>{...})` | unchanged |
| Python `kan.Network([...])`, `model.layers`, `gradients.layers` | unchanged for KAN-only networks; lists may now contain `kan.InputMap` / `kan.InputMapGradients` |
| manual input scaling before `forward` | `kan.Network([kan.InputMap(n, kan.affine_from_range(x)), ...])` |

New errors:

- "layer index does not refer to a KAN layer";
- "network gradient kind does not match the layer";
- the map validation messages ("affine map scale and shift need one value per
  feature", "affine map scale must be nonzero", "tanh map scale must be finite and
  positive", "layer norm epsilon must be finite and positive", "layer norm gain and
  bias must both be empty or have one value per feature", "input map features must
  be positive", "input map is uninitialized or moved from").

`Network::regularization` now checks lambda itself, with the same message and type
as before.

Existing tests, the three frozen benchmarks, the installed consumer and the golden
harness are migrated mechanically:

- tests use `tests/support/network.hpp`: `test::layer`, `test::grad`, `test::layers`;
- benchmarks use `kan_layer`, `kan_grad` and `kan_layers`, which return references,
  so nothing is copied in the timed region;
- the golden harness uses `api::layers` / `api::grad` and selects them with
  `__has_include("kan/input_map.hpp")`, so one `golden.cpp` compiles against both
  APIs.

No assertion changed meaning. `docs/CONTRACT.md` gains the section "Input maps
(backlog M1)". The "no implicit normalization" sentence now points at it, and the
network sentence mentions maps. `README.md` gains an "Input maps" section and a
table row.

### Demonstration (`far_inputs_train_with_map_and_fail_without`)

Samples are `x = 100 … 500` (33 points, all outside `[-1, 1]`). The target is
`0.2 + 0.7u - 0.4u²`, with `u = (x-300)/200`. Training is full-batch SGD on the MSE;
the initial MSE (zero model) is 0.193.

| Network | Result |
|---|---|
| Chebyshev K=5, no map, rate 0.1 | MSE 4.6e42, 2.6e86, 1.5e130 after epochs 1–3; `overflow_error` at epoch 8 |
| affine_from_range → same layer, 400 epochs | MSE 8.3e-20 |
| TanhMap(1/200) → same layer, 400 epochs | MSE 2.4e-4 |
| B-spline on `[-1,1]`, no map, rate 0.5 | coefficient gradients exactly 0, coefficients stay 0; MSE 0.190 (bias only) |
| affine_from_range(−0.999, 0.999) → same spline, 2000 epochs | MSE 7.9e-20 |

LayerNorm is not part of this one-feature demonstration, because one feature
normalizes to zero. It is covered by the gradient, parity and SGD tests.

### CPU/CUDA parity (`input_map_resident_test`)

## Profiling (AGENTS.md rule 6)

Harness: [map_profile.cpp](M1-bench/map_profile.cpp). It runs resident full steps
(forward, backward, SGD) of the R3 reference topology 64→64→32→16, Chebyshev K=7,
batch 1024, with each map kind in front of it.

**Before tuning (`45be1f3`)**:

- Nsight Compute ([ncu-summary.txt](M1-bench/ncu-summary.txt), locked clocks):
  - the map kernels were **FP64-pipe bound**, not memory bound: SM throughput
    46–56%, DRAM 4–9%;
  - LayerNorm forward 17.1 µs and input VJP 15.5 µs, with one warp per row: every
    lane redundantly executed the row's FP64 divisions, 1/sqrt and 10 shuffle-add
    steps for only 2 features per lane;
  - tanh VJP 17.8 µs (FP64 `cosh` plus a division per element);
  - gain/bias partial 8.4 µs (32 blocks) and finish 5.0 µs.
- Nsight Systems per step: LayerNorm+affine 31.3 µs, tanh 19.5 µs.

**Changes (`dcdab6d`)**:

- LayerNorm rows are processed by groups of 1–32 lanes. Each group is sized for
  about 8 features per lane and is a template parameter, dispatched once per launch.
- Blocks have 64 threads. The kernels are latency bound at this size, so 128 small
  blocks spread over all 82 SMs beat 32 large ones.
- Means are `sum * (1/n)`, a shared formula that the CPU uses too.
- The tanh VJP is evaluated from the saved output.
- Row tiles of 16 give 128 partial blocks.
- The finish is one warp per parameter with a fixed butterfly.

**Results:**

| Kernel (1024 × 64) | ncu before | ncu after |
|---|---|---|
| LayerNorm forward | 17.1 µs | 10.5 µs |
| LayerNorm input VJP | 15.5 µs | 11.2 µs |
| gain/bias partial | 8.4 µs | 6.2 µs |
| gain/bias finish | 5.0 µs | 4.3 µs |
| tanh VJP | 17.8 µs | 6.2 µs |
| tanh forward | 9.8 µs | 9.8 µs (FP64 tanh itself) |
| affine forward / VJP | — | 5.2 / 4.5 µs |

Nsight Systems on the final code, at boost clocks
([nsys-kernels.csv](M1-bench/nsys-kernels.csv)), per step:

| Map | Map kernels per step | Share of the step |
|---|---|---|
| LayerNorm + gain/bias | 20.5 µs | 1.1% |
| LayerNorm | 13.1 µs | — |
| tanh | 10.7 µs | 0.6% |
| affine | 5.8 µs | 0.3% |

The basis layers' kernels take about 1.9 ms per step: contraction 240 + 181 + 160 µs
plus the basis kernel, each ×3 layers. Full-step medians are 2.25–2.29 ms with any
map, against 2.25–2.26 ms without one. **The maps are not a bottleneck.** At this size
the remaining time is latency (0.1 waves); the contraction kernels remain the
dominant cost (C2).

## Review

One independent `cpp-reviewer` pass covered `bb45f28..dcdab6d` and found no CRITICAL
or HIGH issues. It verified the VJP derivations, warp uniformity of the grouped
shuffles, inactive groups, batch zero and capacity > batch, partial-buffer sizing,
grid limits, SGD atomicity, moved-from behaviour, and the unchanged launch sequence
and arena layout without maps. Its findings and how each was handled:

- **Fixed (MEDIUM):** `affine_from_range` returned a finite constant map when a
  feature's span overflowed. It now raises `overflow_error`, as it does when the
  scale underflows to zero. Tested.
- **Addressed (MEDIUM, process):** contract, README and this evidence were not yet
  written at review time. The `BACKLOG.md` journal entry is left to the coordinator,
  as instructed.
- **Fixed (LOW):** `AffineMap` accepted zero scales. They are now rejected and
  documented.
- **Fixed (LOW):** a network of fixed maps launched the candidate kernel with
  `blocks(0)` = 65535 empty blocks. The launch is now skipped. Tested.
- **Accepted (LOW):** `Network::regularization` validates lambda before the loop.
  It has the same type and message, and the existing tests pass.
- **Accepted (LOW):** the 64-bit `index % features` in the affine kernels. Both
  affine kernels together take 5.8 µs per step.
- **Accepted (LOW):** the benchmark `kan_layers` builds a vector of references in the
  timed legacy path. It cannot be hoisted, because `Network::sgd` replaces the
  layer storage every step (the former span was refreshed per step as well). The
  M1-host ratio is 0.925.
- **Documented (LOW):** the vector attributes of the Python map classes are copies,
  like those of the basis configurations.

## Open points for later items

- **C1/C2.** The LayerNorm kernels are FP64- and latency-bound at small sizes. FP32 (C1)
  makes them correspondingly cheaper; their share stays about 1% next to the
  contraction.
- **M3/M4.** A residual `silu` branch and the initializers do not depend on maps. Data
  helpers such as `affine_from_range` can feed a spline domain directly.
- **M6.** Per-input grids and quantile refits can reuse `affine_from_range`'s
  per-feature statistics.
