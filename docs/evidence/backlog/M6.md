Finding (BACKLOG M6): knots (and RBF/Mexican-hat centers and scales) are shared by all inputs of

## Scope decisions (AGENTS rule 5)

1. **Per-input grids for B-splines only.** `BSplineConfig::grids` (1 = shared, the default; =
   inputs: one knot vector per input). Gaussian RBF and Mexican-hat dictionaries are
   translation-scale families: a per-input placement of a shared dictionary is an affine map of
   the input, which the explicit `AffineMap` (backlog M1, e.g. `affine_from_moments`) already
   provides; trainable RBFs learn shared centers and widths by gradient; per-edge wavelets
   (backlog M7) learn their own translations and scales. A per-input copy of those
   dictionaries would multiply their resident basis-kernel instantiations for no capability the
   maps and trainable carriers lack. pykan's per-input grid is a B-spline grid.
2. **Equal degree and term count for all grids** (as pykan: grid shape `(in_dim, G+2k+1)`). The
   coefficient layout `(outputs, inputs, terms)`, L2, initializer draw order, `set_parameters`,
   the cuBLAS contraction (C2), the sparse path (C5) and the derivative coefficients (C13) are
   unchanged. Consequence: knot insertion on a per-input layer inserts one knot into every grid
   (`insert_knots`, `adapt_grid(layer, input, batch)`), never into one grid alone.
3. **Existing API is the shared special case.** `BSplineConfig{p, knots}` keeps `grids = 1`; the
   M3 `insert_knot(layer, x)` and `adapt_grid(layer, samples)` keep their behavior and require a
   shared grid; `Network::adapt_grid(index, samples)` still takes samples in the layer's domain.
   The propagated forms are new overloads (`Network::adapt_grid(index, input, batch)`,
   `Network::refit_grids`). `evaluate_basis` of a multi-grid configuration raises
   (`spline_grid` selects one).
4. **Quantile refit = pykan's `update_grid_from_samples`, clamped.** Interior knot
   `j = eps*uniform_j + (1 - eps)*x_(floor(n/G*j))` (pykan's index, `grid_eps` default 0.02),
   coefficients by least squares to the current edge functions at the samples (pykan's
   `curve2coef`), here banded normal equations with a ridge (default 1e-8, pykan's former
   regularized solver; pykan's current `lstsq` is a minimum-norm solve) and an explicit
   "singular" error instead of a silent minimum-norm answer. Our splines are clamped (M3), so
   pykan's `k` extension intervals beyond the samples have no equivalent; instead
   **`GridRefit::margin`** (default 0.01) extends the domain by 1% of the sample range on each
   side. With margin 0 the extreme samples are the clamped endpoints exactly and the slightest
   later change of the preceding layers moves them outside the domain (zero): measured in the
   first version's Python test, a 1e-16 parameter difference changed an output by 0.29.
   `intervals` sets a new term count (pykan's `refine`); `per_input = false` refits one shared
   grid from all values. Degenerate inputs (no interval, coinciding quantile knots, singular
   systems) raise `std::invalid_argument`; nothing changes.
5. **Network propagation as pykan's `update_grid`:** layer by layer, each layer refit on the
   activations of the layers before it after their refit; atomic on the network.
6. **Device refit at a fixed term count.** Knots were configuration of the executor (M3/R9:
   refine on the CPU, rebuild). The measured host route (download, CPU refit, rebuild) is
   721.8 ms against 1.40 ms for a training step of the FP32 256x256x256x10 network,
   i.e. pykan's schedule (10 refits in the first 50 steps) would cost far more than the
   training it adapts. `ResidentNetwork::refit_grids` therefore refits on the device from the
   uploaded batch: knots and knot scales change in place, which keeps the arena, graphs and
   allocations (contract change: the executor's snapshot follows its refit knots, R9 uploads
   compare against them). A change of the term count or grid form still needs the host route
   (new arena).
7. **Shared dense B-spline layers run the new kernel.** Profiling the per-input kernel showed
   that the dense B-spline basis kernel's runtime-degree Cox-de Boor scratch lives in local
   memory (L1-dependent). The new `basis_grid_kernel` (staged knot rows, degree 0..3 at compile
   time) is bitwise the same arithmetic; shared-grid dense B-spline layers use it as one grid of
   every input. Results are unchanged (golden 8/8, hashes); the old instantiations remain
   compiled (SASS-identical) for the other families. This changes the speed of existing B-spline
   layers (below), not their results.

## Design

### CPU (`src/carriers/basis.cpp`, `src/backends/cpu/`, `src/carriers/local/`)

- Validation per grid (`validate_grid`, the M3 checks unchanged); `basis_size` from one grid;
  `Layer` and `set_carrier` require `grids` 1 or `inputs` (`detail::check_grids`).
- `SplineExpansion` reads input `i`'s knots at `knots + i*stride` (stride 0 for a shared grid):
  the sparse CPU engine (C5) is otherwise unchanged, so a shared layer's operations are the same.
- `insert_knots` (Boehm per grid, the M3 arithmetic; `insert_knot` is its one-grid case),
  `adapt_grid(layer, input, batch)` (the M3 rule per grid).
- `refit_grid`: per grid the sorted samples and pykan's knots (`refit_knot`); per input the
  sorted column is cut into runs with one first term on the new and on the current grid
  (`spline_first_term`, the span search of `spline_evaluate`), the run products
  `B_new B_new^T` and `B_new B_cur^T` are summed in sample order (`refit_sample`,
  `spline_values`: the Cox-de Boor values of `spline_evaluate` without the derivative
  expressions), the band of `B^T B` is assembled run by run, `band_cholesky` factors it with the
  ridge, and each output's right-hand side `sum_runs (B_new B_cur^T) c_old` is solved
  (`band_solve`). Cost per input `O(n (p+1)^2 + terms (p+1)^2 + outputs runs (p+1)^2)`:
  the cross Gram form avoids evaluating every edge function at every sample
  (`O(n outputs (p+1))`).
- `Network::refit_grids` / `Network::adapt_grid(index, input, batch)`: one forward
  propagation, refit layers on a copy, then commit.
- Initializers: per-input factors (each grid's moments and variance), the shared-grid path and
  all pinned digests unchanged.

### Resident execution of per-input layers (`src/backends/cuda/resident.cu`)

The knot-reading kernels get per-input variants with new names, so every existing kernel is
SASS-identical: `basis_grid_kernel` (dense rows, staged FP32 tiles and direct FP64/long rows),
`spline_grid_basis_kernel` (sparse rows; the C5 body moved into a force-inlined `spline_rows`
whose shared-grid instantiation compiles to the same SASS), `GridSplineDifferences` (C13 dense
input VJP finish) and `spline_grid_difference_kernel` (C13 derivative coefficients with
per-input knot scales). A grid-stride loop's input index advances incrementally
(`RowInput`: one 64-bit remainder per thread). The plan reserves `grids` knot vectors and
knot-scale rows; the forward, contraction, sparse sort and parameter kernels do not read
knots and are unchanged.

### Device refit

`ResidentNetwork::refit_grids` runs the forward pass layer by layer and, before a B-spline
layer's forward, refits it from its input activation:

| step | implementation |
|---|---|
| transpose `(batch, inputs) -> (inputs, batch)` | existing `transpose_kernel` |
| sort per input (and all values for a shared grid) | CUB `DeviceSegmentedRadixSort::SortKeys` (`DeviceRadixSort` for the pooled sort) |
| knots per grid | `refit_knots_kernel` (one thread per grid; T-rounded, strictly increasing check, C13 knot scales) |
| runs `(input, g, g')` | CUB `DeviceRunLengthEncode::Encode` over a `thrust::transform_iterator` computing the key per sorted sample (no key array), CUB `DeviceScan::ExclusiveSum` for the offsets |
| run products | `refit_run_kernel`: one warp per run (degrees 0..3), lanes over the run's samples in order, fixed shuffle tree; one thread per run otherwise |
| normal matrix and factor | `refit_factor_kernel`: one thread per input, runs in order, `band_cholesky` |
| right-hand sides and solve | `refit_solve_kernel`: one thread per (input, output), `rhs[(i*terms + k)*outputs + o]` (coalesced), `band_solve`, rounding to T |

Atomicity: the active parameters are copied to the candidate region, which becomes active; the
refit writes its coefficients there and reads the old ones from the previous region; every
refit layer's knots and knot scales are backed up first. A failure (status bits 8, 16, 32 per
layer, checked after each layer) swaps the regions back and restores the knots. Workspace
(reserved after every other region, largest B-spline layer at capacity, `R = inputs *
min(capacity, 2 terms + 1)` runs): transposed and sorted samples `2*inputs*capacity` T,
run keys/counts/offsets `16 R` bytes, run products `16 (p+1)^2 R` bytes, bands
`8 inputs terms (p+1)`, right-hand sides `8 inputs terms outputs` bytes, staged and double
knots, backups of all spline layers' knots, CUB temporary storage.

solve launch, 128/64 threads per refit block), not device-specific constants.

## Open questions for the owner

- The C5 sparse-path selection constants were fitted against the previous dense FP32 B-spline
  kernel, which is now 1.4-1.8x faster at small term counts; the crossover (`terms/(degree+1)`
  4 FP32, 5 TF32) may have moved. Not re-swept here (it is a selection change for existing
  layers, independent of per-input grids).
- The refit workspace (7-9% of the measured B-spline arenas) is reserved for every network
  with a B-spline layer, used or not. Aliasing its sample buffers onto the refit layer's own
  basis rows (overwritten by its next forward) would remove most of it but needs a fallback
  where those rows are smaller; an opt-out at construction is the alternative.
- Gaussian/Mexican-hat dictionaries keep one grid per layer (scope decision 1); per-input
  centers would be a separate item.
- pykan's current solver is a minimum-norm `lstsq`; ours is the regularized normal-equation
  solve with an explicit singular error. With the default ridge (1e-8) a span without samples
  gets near-zero coefficients, as pykan's former solver.
- The launch-size choices were measured on GB10 only; on an RTX 3090 the grid bound comes from
  its 82 multiprocessors and the occupancy queried per instantiation, and sm_86 compiles
  without spills, but no sm_86 device was available.
