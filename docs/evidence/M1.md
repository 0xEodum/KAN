# M1 numerical foundation: final evidence

Source: [introduction.md](../../introduction.md), with journeys and numerical
requirements resolved in [CONTRACT.md](../CONTRACT.md). Validation date: 2026-09-30.

## Delivered behavior

- Select Chebyshev, Legendre, Jacobi, physicists' Hermite, Fourier or Gaussian RBF
  expansions, obtaining values and analytic input derivatives.
- Configure owned batched dense KAN layers and arbitrary compatible mixed-family
  networks, evaluate edge functions and backpropagate an externally supplied loss.
- Train with explicit SGD and batch scaling; invalid updates are atomic across
  all network layers. Nonfinite data, bad shapes and numerical overflow fail explicitly.
- Use an optional original CUDA Chebyshev forward/VJP backend with owned per-call
  buffers and streams, fixed-order reductions and CPU-compatible overflow semantics.
- Install a static CMake package and compile independent CPU/GPU consumers.

No external KAN source or interfaces were ported. CPU needs only C++20 and CMake;
CUDA is a separate optional target. Python is used for coverage reporting only.

## Independent review

A separate agent performed read-only review of all source/header files, tests,

After the corrections, the reviewer independently rebuilt with GCC Release:

audit is pending publication of this report.

## Practical limits and next stage

CUDA M1 supports Chebyshev layers with synchronous host transfers and allocations;
no persistent GPU tensors, GPU SGD, multilayer CUDA wrapper, Python bindings or
speedup claim. RBF centers/widths and Jacobi/Fourier configuration are fixed, not
trainable. Extreme high-order/outside-domain polynomials can overflow; values near
endpoints with extreme Jacobi parameters can be ill-conditioned despite stable
exact endpoints. No implicit normalization/clipping is applied.

Wavelets, splines, rational and quantum carriers remain roadmap work. The next
stage is persistent GPU execution and all existing basis families, then bindings
and matched full-call benchmarks. Local GCC testing ran on Windows/UCRT64;
Linux/Windows hosted CPU CI is configured but had not run at report creation.
The existing unrelated Python implementation on remote `main` is preserved;
this original C++/CUDA project is published separately on `cpp-foundation`.
